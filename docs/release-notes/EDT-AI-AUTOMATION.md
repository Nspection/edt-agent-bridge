# Автоматизация EDT и Vanessa для ИИ-агентов

Начинать с MCP-команд `edt_capabilities` и `edt_runner_profile` (`project`, `action=get`). Не искать заново пути платформы, Vanessa или тестовой базы и не открывать дополнительные сеансы наугад.

## Профиль рабочего места

`edt_runner_profile(action=put)` сохраняет профиль проекта в `.metadata/.plugins/com.codepilot1c.core/runner-profiles` текущего workspace EDT. Другие агенты, подключённые к этому EDT, получают те же настройки через MCP. В другом workspace нужна собственная однократная настройка. Профиль не содержит пароли и произвольные команды ОС.

Обязательные поля: `platform_bin`, `infobase_path`, `manager_infobase_path`, `vanessa_epf`, `params_template`, `expected_vanessa_sha256`. Пути абсолютные; SHA256 относится к основному EPF Vanessa. Необязательные: `user_name`, `manager_user_name`, `configuration_name`, `timeout_s`, `visual_checkpoint`. Пустое имя пользователя служебной базы допустимо.

Целевая база и база менеджера разделены. Расширение `client_mcp` устанавливают в выделенную базу менеджера; `VAExtension` в тестовый клиент требуется для зависящих от него операций. Не устанавливать расширения в бизнес-базу без соответствующей задачи.

## Однократная подготовка

1. Получить `edt_runner_profile(project=..., action=get)`. `configured=false, state=needs_setup` означает отсутствие первоначальной настройки. Не запускать клиента повторно и не просить подтверждать отдельные библиотеки.
2. Вызвать `edt_runner_prepare(project=...)`: по умолчанию это просмотр/проверка. Он проверяет хеш EPF, разделение баз, цепочку `ConfLocation` и прежние правила текущего менеджера.
3. Для согласованной подготовки выполнить `apply=true`. Правило разрешает внешние обработки только в выделенной базе менеджера. Другие правила сохраняются; файлы резервируются. Запись в Program Files может требовать однократной настройки администратором. Отказ прав — причина `needs_setup`, а не повод нажимать «Да» на возникающие окна или отключать защиту для всех баз.
4. Проверить `edt_runner_extension(project=...)`. Он читает свойства `client_mcp` через нативную сессию Designer. Для выделенной базы менеджера нужны active=true, safe_mode=false и unsafe_action_protection=false; изменение `apply=true` принимает `expected_state_sha256` свежей проверки и не затрагивает расширения целевой базы.
5. Перезапустить только управляемый менеджер. В автоматическом запуске используются явные VAParams, `QuietInstallVanessaExt` и `DisableFirstRunHelper`. Проверить `edt_runtime_catalog`: TCP-соединение само по себе не подтверждает готовность Vanessa. `ready=false` означает отсутствие регистрации её инструментов.

Изменение EPF с другим хешем требует проверки обновления и сохранения нового хеша в профиле. `prepared` означает согласованность настройки, а не прохождение сценария.

## Обычный прогон

`edt_development_run_start(project=..., profile_id=default, idempotency_key=..., update_db=false)` возвращает `run_id`. `update_db=true` задавать явно, когда обновление целевой тестовой базы разрешено задачей.

Опрос: `edt_development_run_status(run_id, after_sequence)`. События отражают подготовку, обновление схемы, запуск, текущий шаг, паузу отладчика, визуальную контрольную точку и завершение. Пауза отладчика исключается из watchdog; внутренние таймауты отдельных шагов Vanessa независимы.

На визуальной точке прочитать снимок и передать актуальные `run_id`, идентификатор точки и SHA256 в `edt_development_run_continue`. Не подтверждать старый снимок и не считать статус запуска подтверждением успеха. `edt_development_run_cancel` завершает только процессы своего прогона.

Обновление схемы не подтверждает завершение обработчиков прикладного обновления БСП. Для них нужны отдельные проверки состояния приложения.

## Работающий интерфейс

`edt_runtime_catalog` возвращает фактические схемы Vanessa. `edt_runtime_observe` читает состояние и интерфейс; `edt_runtime_action` выполняет семантические действия по элементам формы и требует `idempotency_key`. Результат асинхронного действия читать через `edt_operation_status`.

Поиск доступных шагов и настройки Vanessa доступны через этот же каталог. Изменение `useaddin` через `manage_va_settings` само по себе не инициализирует компоненту: она подключается при запуске с явными VAParams. Операции интерфейса и снимков Vanessa могут требовать подключённого TestClient. Для первоначальной диагностики процесса, пока Vanessa ещё не готова, использовать `edt_process_snapshot(action=list)`, затем `action=snapshot` с возвращёнными PID, временем запуска и window_id. Он снимает только окна 1С/EDT через PrintWindow, не меняет фокус и не посылает ввод; модальные окна перечисляются отдельно. Полностью пустой снимок помечается blank; он не подтверждает готовность.

Снимки используются для анализа. Нажатия мышью/клавиатурой через Computer Use в автоматическом сценарии не нужны.

## Создание и проверка метаданных

`edt_creation_defaults` показывает значения, назначенные фабрикой EDT для версии платформы проекта. `create_metadata`, `add_metadata_child` и `create_form` используют штатные фабрики; генерация управляемой формы выполняется EDT. Явно заданные значения перекрывают эти умолчания, включая квалификаторы типов.

Различать эффективное значение модели, `model_is_set`, EMF default и наличие XML-узла. Пропуск XML-узла не доказывает эквивалентность умолчаниям платформы. После изменения проверять сохранённые артефакты и диагностику нужного проекта: `get_diagnostics(scope=project, project_name=..., max_items=100)`.

Перед удалением: `edt_delete_preview`, затем одноразовая валидация и `delete_metadata`. Нативный рефакторинг EDT обрабатывает ссылки; запреты самой платформы нельзя обходить параметром force.

## Дополнительные команды модели и предпросмотра

- `edt_rename_metadata`: предпросмотр штатного рефакторинга EDT, применение по `expected_preview_sha256`; UUID сохраняется, запреты EDT не обходятся. Формы и визуальные элементы требуют отдельного form-aware механизма и этой командой не переименовываются.
- `edt_predefined`: чтение, создание, изменение и удаление предопределённых данных справочников и планов видов характеристик/счетов/расчёта. Изменение требует свежего хеша предпросмотра. При изменении существующего элемента UUID сохраняется; у предпросмотра нового UUID предварительный. Удаление папки включает потомков. Доставка в существующую базу требует обработки обновления; команда её не выполняет.
- `edt_spreadsheet`: разреженные ячейки, параметры, форматы, объединения, именованные области, размеры колонок/строк. Координаты MCP начинаются с **1**; внутри модели EDT пересчитываются с 0. Предпросмотр клонирует также не содержащиеся напрямую объекты колонок. Применение требует хеша; чужой вид макета не преобразуется. Новый документ создаётся штатным `SheetFactory` с контекстом проекта. Уже существующий, но не загруженный внешний файл не перезаписывается.
- `edt_change_set`: `begin` фиксирует явно указанные существующие файлы и текущие маркеры диагностики. `status` возвращает хеши и изменения диагностики. `write_text` с `expected_sha256` записывает UTF-8 текст BSL/feature/JSON/MD/TXT и отмечает именно собственную запись. `rollback` восстанавливает только такие записи, если их хеши с тех пор не изменились. Сам снимок не разрешает откат последующих изменений. XML метаданных здесь наблюдается без текстового отката; для него нужны нативные операции. Маркеры читаются в текущем состоянии, завершение фоновых проверок не подразумевается.
- `edt_editor_form_preview`: список элементов и вложенных страниц формы, выбор по имени/ID штатной моделью EDT с открытием содержащих страниц; `capture=true` возвращает снимок. Для нативного рендера состояние `native_renderer_capture_required` означает необходимость посмотреть снимок, а не ошибку формы. Поле `selection_source` отличает текущее выделение от последнего запроса выделения нативному редактору.
- `edt_editor_gallery`: последовательные снимки страниц формы, до 20 за вызов, с восстановлением предыдущего известного выделения. Возвращает ошибки отдельных страниц и статус восстановления; наличие PNG не является автоматическим заключением о корректности интерфейса.

`edt_capabilities(include_schemas=true)` возвращает фактически зарегистрированные схемы команд и короткие последовательности работы. Агенту не нужно заново искать возможности Vanessa в её исходниках.
