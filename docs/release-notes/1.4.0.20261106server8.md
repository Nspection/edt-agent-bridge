# EDT Agent Bridge 1.4.0.20261106server8

## Новые возможности

`edt_infobase_provision(kind="server")` поддерживает создание серверной информационной базы через native launcher EDT, загрузку DT, проверку доступа экспортом конфигурации, привязку приложения к проекту и полную первую загрузку с проверкой `EQUAL`. Для восстановления существующей ИБ обязательно явное `restore_existing=true`; предварительно EDT создаёт backup DT.

Режимы `server_operation`: `create`, `restore`, `bind`. Новые имена ИБ и SQL-базы формируются с UUID. Preview возвращает `creation_id` и `preview_sha256`; apply требует сохранить creation_id и передать expected_preview_sha256. Повторное использование creation_id запрещено, включая частичный сбой. Ошибка не приводит к автоматическому удалению базы: этап и каталог операции сохраняются для диагностики.

Управляемый прогон Vanessa принимает `server_address` и `server_infobase` вместо файлового пути. Менеджер тестирования остаётся отдельной файловой базой. Состояния, JUnit, визуальная контрольная точка со снимком и продолжение по SHA256 доступны через существующие MCP-команды.

## Исправления

- Повторная привязка отключает прежнюю native-синхронизацию до смены runtime/доступа, исключая гонку переподключения.
- После восстановления DT настройки доступа EDT переключаются на нового пользователя до проверочного экспорта; existing_* применяются к старой базе, login/password — к восстановленной.
- Простая привязка сохраняет отложенное требование полного обновления.
- Клиент 8.3 запускается без неподдерживаемого ключа `/i85`.
- Минимальный шаблон параметров допускает визуальную контрольную точку без предварительно заданных служебных каталогов.
- Контроллер явно включает VanessaExt и захват процесса; IrfanView не требуется. Временные параметры удаляются после остановки принадлежащих прогону процессов.
- Пароль клиента берётся из штатного хранилища EDT и передаётся контроллеру через stdin, без записи в профиль/состояние. Стандартный клиент 1С далее использует /P; пароль может быть виден локальному администратору процессов.

## Проверки и ограничения

288 Java-регрессий и 24 PowerShell-проверки прошли. Живая проверка выполнена в отдельной EDT 2026.1.2.2 / JDK 17 на разрешённом кластере 1С 8.3.27.2325 с PostgreSQL: create/restore/bind, backup, full reload, перепривязка после перезапуска, смена пользователя после DT, сценарий Vanessa и PNG с продолжением по SHA256. Итоговый визуальный сценарий: 1 тест, 0 ошибок; клиенты автоматически закрыты.

Все тестовые ИБ, SQL-база, проекты, DT, регистрации запуска и собственные процессы удалены. Сохранность исходных баз проверена отдельно. [Подробный протокол](../../agent-bridge/server-infobase-validation.md).

MS SQL заявлен в схеме, но вживую не проверялся. Параметры административной аутентификации кластера не добавлены. Серверный preview не является снимком живых данных. `edt_project_from_application` пока остаётся файловым. Равенство схем не подтверждает прикладные миграции.
