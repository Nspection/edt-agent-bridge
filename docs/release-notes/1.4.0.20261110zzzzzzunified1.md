# EDT Agent Bridge 1.4.0.20261110zzzzzzunified1

Единая подготовка среды через `edt.run op=prepare`: агент проверяет привязку проекта к точному UUID и native EQUAL, готовит Python и запускает собственный TestClient либо внешний Native host. Для Vanessa проверяет существующее настроенное окружение. Загрузка конфигурации, привязка базы и разрешения доверия остаются отдельными действиями.

- Сохранение IDs до запуска, повтор ключа возвращает первоначальную подготовку. Неизвестный исход не обходится новым ключом или другим исполнителем.
- Уборка по preview/hash удаляет только созданные подготовкой ресурсы; заимствованные Python и Vanessa сохраняются.
- Тонкий TestClient ждёт полный оставшийся startup-бюджет: прежний вложенный лимит10с мог закрыть канал раньше общего ожидания90с. `client_kind=thick` — явный выбор, автоматического fallback нет.
- После разрешения доверия Native-подготовка сохраняет подтверждённую готовность. Запуск помощника рядом требует свежей проверки исходного канала.
- Тяжёлая подготовка использует общую очередь EDT. Компактный каталог сохраняет десять входов; прежние команды доступны напрямую.

Проверки: 775 Java-тестов,35 worker- и16 table-контрактов, standalone boundary и p2. На TMS_FILE85 / Windows x64 / 1С8.5.1.1522 выполнены три прямых thin-запуска и один через `edt.run`, с чтением интерфейса и подтверждённой уборкой. Исходный отказ был плавающим; старый статус не сохранял тип исключения, поэтому причина каждого исторического сбоя не объявляется доказанной. Эти прогоны проверяют запуск/чтение, не всю прикладную конфигурацию.
