# EDT Agent Bridge 1.4.0.20261106runtime3

Выпуск от 6 ноября 2026 года. Windows x64, EDT 2026.1.2.2, JDK 17; native-проверки на платформе 8.5.1.1522 в отдельной EDT Agent Bridge Dev.

## Базы и приложения

- `edt_infobase_provision`: preview/apply, новая файловая ИБ, восстановление DT, проверка доступа экспортом конфигурации, привязка приложения и native FULL reload с подтверждением EQUAL.
- Замена существующей ИБ разрешается явно; перед ней выполняется обязательная native резервная выгрузка DT. Старые и восстановленные учётные данные задаются раздельно.
- Первое обновление после create/restore всегда полное. Отложенное обновление сохраняет этот признак в workspace между перезапусками; маркер снимается после EQUAL.
- `edt_project_from_application`: новый проект из ИБ через native EDT; обновление существующего — через собственный снимок и штатное compare/merge, с просмотром плана пользователем или применением агентом.
- Явный перенос приложения между проектами; без указания владельца чужая привязка сохраняется. Ограниченная уборка собственных неизменённых снимков.
- `edt_operation_status` показывает этап, историю и результат фонового задания. Поддержан `full_reload` в штатном обновлении ИБ через MCP.

## Исправления ревью

- Общая защита от конкурентных MCP restore/update, включая обычное обновление приложения и определение фактического режима. Ошибка фонового обновления теперь даёт FAILED, а не DONE с ошибкой внутри результата.
- DT повторно проверяется перед загрузкой после backup. Пароль без логина отклоняется до изменения базы.
- Настройки UPDATE закрепляют точную сборку платформы; используется native DesignerSession pool, не конкурирующий CLI-процесс.
- Не снимается обязательность full reload при ошибке проверки равенства.
- Очистка учитывает файлы вне src, ссылки и несохранённые редакторы; путь проекта и базы не могут пересекаться.
- Маскирование секретных аргументов до записи в логи и трассу; native ошибки также очищаются. LinkageError переводится в FAILED.
- Сохранён правильный параметр Vanessa `ShowMainForm=Ложь`; добавлена регрессионная проверка его кодировки.
- Дерево native-сравнения не падает на FeatureComparisonNode без разрешённого related feature: узел возвращается с явным `path_resolved=false`.

## Проверки и ограничения

265 standalone-регрессионных тестов и проверка состава дистрибутива. Подтверждены 10 проверок native-цикла, отдельная проверка full reload после перезапуска и p2-план обновления в изолированном профиле. Живой цикл проверяет создание/загрузку тестового DT, полную загрузку до EQUAL, импорт модели и привязки, native merge с удалением лишнего объекта, backup перед повторным restore и уборку проектов. Пользовательская TMS для испытаний не перезапускается.

Поддерживаются локальные файловые ИБ. Серверные restore DT этим интерфейсом не реализованы. Успех синхронизации конфигурации не означает успешного выполнения прикладных обработчиков обновления БСП. Живой DT в воспроизводимом аудите без пароля; маршрутизация старых/восстановленных учётных данных и защита секретов покрыты регрессионными тестами, но отдельный DT с парольными пользователями в этом выпуске не проверен.

## Обновление

В EDT: **Справка → Проверить обновления**. Сайт: `https://nspection.github.io/edt-agent-bridge/`. После установки перезапустите EDT и обновите список инструментов у MCP-клиента. Bundle/feature ID сохранены для обновления на месте. Bridge заменяет CodePilot; параллельная установка не поддерживается.

Авторство и AGPL сохранены. EDT SDK, платформа 1С, Vanessa, тестовые базы, дампы и локальные учётные данные в поставку не входят.
