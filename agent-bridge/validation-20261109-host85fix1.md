# Проверки Native host 8.5

Выпуск: 1.4.0.20261109zzhost85fix1. Пакет собран против SDK EDT 2026.1; 632 Java-исходника. Полный набор: 658 Java-тестов и проверка standalone product boundary. P2-пакет проверяется директором в отдельном профиле с verifyOnly; пользовательская EDT при выпуске не меняется.

## Runtime до релизного ревью

На 1С 8.5.1.1522 выполнен полный цикл metadata host: создание, FULL, запуск внутренней формы обработки, клиентский и серверный вызовы через Native API, удаление исходников, FULL и независимый runtime-запрос отсутствия обработки. Имя формы в Hello и клиентском результате имело вид Обработка.BridgeAgentHost<id>.Форма.Host, оба вызова завершились terminal=true/state=completed/execution.success=true с ответом 42; сервер дополнительно подтвердил наличие временного объекта в метаданных.

Проверены отказ канала с transport_failed, запрет новых команд после сбоя, outcome_unknown без автоматического replay, recovery через другой живой host той же базы, повтор verifier без лишнего FULL, удаление осиротевшей регистрации при отсутствующих файлах и сохранение изменённых исходников. Собственные частные базы, проекты и клиенты убраны; исходные настройки доверия восстановлены. В пользовательской тестовой базе убраны два прежних остатка и новый host, для metadata подтверждено отсутствие объекта в базе. Git прикладного проекта чистый.

Этот живой полный цикл пройден на локальной fix6. Fix7 добавила общую reentrant-блокировку disconnect/FULL, не меняя байты HostForm, NativeHostService, NativeHostChannel и EdtRuntimeHostTool. Релиз дополнительно исправляет только кириллицу описания MCP и документацию; полный runtime-цикл после этих изменений не повторялся. Статические тесты выполнены на релизной сборке.

## Ограничения

После успешной уборки до перезапуска EDT показывала EQUAL, после перезапуска — NOT_EQUAL. Причина не установлена; текущую синхронизацию всей конфигурации считать неподтверждённой. Повторный FULL для сокрытия статуса и ручная установка равенства не выполнялись.

SDK хранит synchronization flows под общим APPDATA/.1cedt/ib-sync/flows с процессным счётчиком. Частные EDT для параллельных испытаний изолированы через APPDATA; процесс, удаливший исходный flows/3, не установлен. Гипотеза пересечения процессов не выдаётся за доказанную причину инцидента.

Разрешения платформы на EPF и подключение бинарной компоненты сохраняются. Native ZIP не изменён, SHA256: 2c59bf99cf8ede8b04654058786bfa424ff0e252dc3f5fac2a875fb5e40df580. Актуальную EPF собирает prepare из шаблона этого выпуска; прежняя статическая EPF не включена как исправленный host.
