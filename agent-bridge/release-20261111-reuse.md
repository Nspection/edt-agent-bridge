# EDT Agent Bridge 1.4.0.20261111reuse1

Повторное использование собственного TestClient в рамках задачи: первый UI-пакет удерживает клиент, следующие ссылаются на исходный ui_run_id. Перед каждым пакетом проверяются проект, UUID, native EQUAL, вид клиента, процесс и канал. Python и процесс заново не запускаются; неизвестный исход блокирует продолжение, автоматической замены клиента нет.

Обычные ответы компактнее: итог, число проверенных шагов, индекс отказа, diagnostic.code/next_step и details_call. Полный результат и тайминги сохраняются. Компактный каталог объясняет выбор Native для BSL/данных, TestClient для поддерживаемого UI, Vanessa для неподдерживаемых действий/явных сценариев. Native может помогать с данными той же подтверждённой базы.

Ревью и независимое ревью исправили ложное освобождение пакета при незакрытой сессии: известный отказ собирается по точному operation_id без признания теста успешным. Ошибка закрытия блокирует продолжение; повтор уборки только собирает прежний результат. Флаг удержания очищается после уборки владельца.

Проверки: 821 Java-тест, 41 worker- и16 table-контрактов, standalone boundary и p2 verifyOnly. Собственная EDT/1С8.5.1.1522: один PID на несколько пакетов, известный отказ и закрытие сессии, уборка исходного клиента. Прежний контрольный ответ был на65.2% меньше details в байтах; это не измерение токенов. Карта/ЦО TMS и серверный кластер не проверялись. Бизнес-данные не откатываются автоматически.
