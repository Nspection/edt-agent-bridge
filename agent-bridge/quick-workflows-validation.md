# Проверка короткого рабочего цикла — 2026-11-08

Релиз: `1.4.0.20261108workflow5`. Windows x64, отдельная EDT 2026.1.2.2 / Java 17, файловые базы 1С 8.3.27.2325, Vanessa Automation 1.2.043.47.

## Автоматические проверки

462 Java-регрессии на финальных JAR и 24 контракта контроллера PowerShell прошли. Проверены страницы/разрывы истории, отсутствие повторных событий, ограничения строк и структурированного CurrentStep, совместимость полных ответов, отказы конфликтующим аргументам, повтор после перезапуска и утрата снимка при сохранённом ключе. Локальный штатный p2 verify-only прошёл в отдельном профиле.

## Живой цикл через MCP

- Два проекта и две файловые базы созданы через native EDT: целевая и отдельный менеджер. Каталоги AuditItems/AuditExtra/AuditFinal созданы фабрикой EDT; последние добавлены после первой загрузки для реального обновления схемы.
- edt_check(update_db=true) выполнил обновление, запустил EDT-отладку и Vanessa. Открыт список AuditItems; на финальном снимке виден новый AuditFinal. Снимок просмотрен, актуальный checkpoint подтверждён по ID и SHA256. Итог: completed, Tests=1, Failures=0; собственные клиенты закрыты.
- Намеренно неверный ожидаемый заголовок дал failed, Tests=1, Failures=1; ошибка не стала ложным успехом. Повторено на финальной сборке.
- Отмена на визуальном checkpoint дала cancelled и закрытие собственных процессов.
- Повтор start с тем же ключом в одной сессии возвращал тот же run ID. После перезапуска EDT/обновления до финальной сборки сохранённый ключ вернул прежний completed-прогон, без нового запуска.
- Сводка подтвердила готовность модели, UUID/имя и EQUAL выбранной базы; чужой для проекта run_id отклонён. Регистрация MCP при старте отдельно от готовности модели: перед изменением дождались READY через сводку.

На одном завершённом успешном прогоне полный JSON ответа занял 4007 символов, компактный — 868. Это измерение размера ответа на данном сценарии, а не универсальная оценка токенов модели.

## Уборка

Оба проекта удалены через native EDT, обе базы и корень фикстуры удалены. Профиль, собственные записи контроллера/прогонов и точные записи запуска убраны; отсутствие файлов и записей проверено. Временное правило доверия только к базе менеджера добавлялось через UAC и после тестов удалено с сохранением остальных правил. Своя EDT/JVM закрыта; пользовательская EDT и рабочие базы не затрагивались. Отчёты и снимки сохранены в игнорируемом .runs/release-workflow3/evidence.

Проверка этого выпуска не повторяет серверный DT-цикл и не сертифицирует произвольные бизнес-сценарии или обработчики миграции данных. Native host в этом выпуске не менялся. Публичные файлы и штатный p2-план проверяются после публикации.
