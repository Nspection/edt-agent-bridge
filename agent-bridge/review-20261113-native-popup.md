# Ревью popup1 и границы приёмки

Собственное и независимое Astra medium ревью охватили текущие изменения запуска Native, владение Win32 desktop/process/handle, ABI, event hook, GDI, BSL batch, запись снимков и компактные квитанции. Это ревью изменения popup/isolation, а не новый построчный аудит всего исторического проекта.

Исправлены замечания: событие новой карточки/child HWND не потребляет меню; кадр содержит именно живой qualifying HWND; прямой Screenshot не сбивает arm, Cancel сбрасывает expectation; disarmed завершается ошибкой; popup expectation запрещён для wait/server; failure screenshot не ждёт popup и не использует ранний кадр; terminal/failure освобождает hook. Валидация capture header идёт до PNG, ошибочная запись sidecar убирает PNG. Время захвата отделено от upload.

Перенос presentation в refresh и effective legacy status проверены. Concurrent start сравнивает режим внутри host lock; active visible не выдаётся как успешный isolated. Desktop создаётся на отдельном коротком потоке с восстановлением исходного desktop, а ошибочное освобождение ждёт завершения потока. Child создаётся suspended для стабильного ProcessHandle и exit cleanup, затем resume. Исправлено лишнее цитирование ENTERPRISE/ключей: именно оно вызвало exit1 до подключения 1С на раннем прототипе. GUI fallback/desktop switch отсутствуют. При cross-thread WM_PRINT timeout нет повторного неограниченного PrintWindow; PID видимых вложенных окон проверяется отдельно.

Полный набор: 1263 Java, 179 Python, PowerShell 33 controller +3 CLI +13 startup, OSGi/boundary/provenance. Дополнительно guarded actual-DLL test: 60 desktop create/close, caller desktop unchanged, popup уничтожен до upload, 3 ожидаемых RGB-строки найдены в PNG. Первоначальный PrintWindow возвращал success с пустым popup; это обнаружила проверка пикселей и исправил WM_PRINT. Передача успешного PNG сама по себе не считается семантическим доказательством.

Финальные bytes приняты в собственных Native metadata-host 8.3.27.2325 и8.5.1.1522 на отдельных скрытых desktops. На обоих PNG визуально проверены Alpha/Beta/Gamma. На8.5 дополнительно: absent popup => failed/no snapshot/no unknown; BSL error + screenshot_on_failure => current snapshot armed=false; несовпадающий start mode => FAILED до нового запуска; compact сохраняет capture provenance без image_path. Свежая внешняя EPF собрана штатным EDT из точного текущего HostForm.bsl. p2 verifyOnly прошёл на копии профиля.

Тестовые клиенты/EDT остановлены. Две целиком одноразовые ИБ удалены по owned_base_id/base_uuid и свежим preview/hash; пользовательские ресурсы не использовались. Удаление временных metadata-объектов из этих баз обеспечено удалением целых disposable ИБ; индивидуальный Native cleanup/database_verified_absent в этой проверке не заявляется. Собственные внешние host cleaned=true, fixture-проекты закрыты и сохранены для воспроизведения. Образцы PNG и журналы остаются только в собственной тестовой области.

Ограничения: screenshot observer следит за текущим UI-потоком; не обещает перехват любых popup других GUI-потоков или проверку конкретной TMS. Число surfaces не равно числу пунктов; pixel_content_verified остаётся false. Same-thread рендер и синхронный BSL не прерываются capture deadline. Startup input на isolated desktop недоступен; интерактивный trust требует явного visible bootstrap. Текущий Desktop не активируется/восстанавливается эвристически. Историческое удаление антивирусом остаётся неклассифицированным; ранее заблокированные артефакты не восстанавливались и не использовались. При финальной сборке AMSI/File_Monitoring running, новых событий4662 в журнале Kaspersky за окно наблюдения нет; это не доказательство отсутствия любых угроз.
