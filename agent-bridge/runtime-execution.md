# Исполнение в базе и внешние проекты

## Граница каналов

`edt_runtime_execute` использует уже сохранённый `edt_runner_profile`, управляемый запуск Vanessa и VAExtension в целевой базе. Код исполняется в TestClient, никогда в базе менеджера. Команда не устанавливает расширения и не обновляет конфигурацию. Перед исполнением проверяются File либо Srvr+Ref профиля; существующая проверка привязки EDT остаётся обязательной. Клиентский контекст означает сеанс управляемого тестового клиента, а не произвольную уже открытую форму пользователя.

Подготовка: отдельная база менеджера, проверенный EPF Vanessa и VAExtension в целевой базе. `edt_runner_prepare` задаёт точечное доверие к библиотекам только в базе менеджера; при записи защищённого conf.cfg могут понадобиться права администратора. `client_mcp` нужен для semantic UI через `edt_runtime_catalog/action/observe`; самому сценарию выполнения BSL достаточно Vanessa и VAExtension. Расширение клиентского MCP не заменяет VAExtension в целевой базе.

## Создать проект внешних отчётов и обработок

`external_manage(command=create_processing|create_report)` создаёт **отдельный EDT-проект внешних объектов и первый объект**, а не объект основной конфигурации. Используется `IExternalObjectProjectManager.create` и фабрика EDT. `project` — существующий базовый проект конфигурации, `external_project` — имя нового внешнего проекта, `project_path` — его абсолютный путь. Для каждого создания сначала вызвать `edt_validate_request(operation=external_manage, payload=<те же аргументы>)`, затем передать возвращённый `validation_token` без изменений. Схема установленного MCP остаётся источником точных параметров.

```json
{"command":"create_processing","project":"TestConfiguration","external_project":"Diagnostics","project_path":"C:/Work/Diagnostics","name":"Diagnostics"}
```

Для отчёта указать `create_report`. `list_projects/list_objects/details` проверяют созданную модель. Модули создавать `ensure_module_artifact` в самом внешнем проекте; FQN имеет вид `ExternalDataProcessor.Diagnostics` либо `ExternalReport.Diagnostics`. Формы и реквизиты создаются обычными model-aware командами, с проверкой фактических defaults.

## Сборка

Сохранить изменения редакторов. Вызвать `edt_external_build(project, external_project, object_fqn)` и дождаться `edt_operation_status.state=DONE`. Native `IExternalObjectDumper.dump` использует штатные преобразование и настройки приложения EDT. Ответ содержит `artifact_path`, `artifact_sha256`, `bytes`; файл находится в `.metadata/.plugins/com.codepilot1c.core/external-artifacts`, вне Git. После использования `edt_external_build(action=cleanup, artifact_path=..., expected_artifact_sha256=...)` удаляет только собственный артефакт с проверкой хеша. Стандартный автоматический `bin` внешнего проекта — отдельный механизм EDT, его артефакты также не следует коммитить. Ошибки блокировки/платформы возвращаются как ошибка сборки без обхода EDT.

## Исполнение

Общие аргументы старта: `project`, при необходимости `profile_id`, уникальный `idempotency_key`, `mode`. Параметры передаются JSON-объектом `parameters`; внутри кода доступны как `ПараметрыВызова`. Присвоить JSON-совместимый результат переменной `Результат`.

```json
{"project":"TestConfiguration","mode":"execute","context":"server","idempotency_key":"probe-001","parameters":{"amount":41},"code":"Результат = ПараметрыВызова.amount + 1;"}
```

Режимы:

- `info` — имя/версия конфигурации, пользователь и платформа.
- `execute` — клиентский или серверный BSL; код до 128 KiB. `context=server` по умолчанию.
- `query` — серверный запрос из `query`, параметры из `parameters`, `limit=1..1000` ограничивает выдачу. Ограничение выдачи не ограничивает объём работы самого запроса. Непримитивные ячейки возвращаются как type/presentation; это не API восстановления ссылок.
- `external` — серверный вызов экспортной **функции** EPF/ERF. Передать `artifact_path`, полученный SHA256 как `expected_artifact_sha256`, имя `method` и `parameters`. Функция принимает один аргумент. Бинарные данные передаются на сервер средствами платформы через сценарий, путь локального ПК на сервере не используется. Для передачи используются временное хранилище и native `ВнешниеОбработки/ВнешниеОтчеты.Подключить`; явные файлы на сервере не создаются. Используется безопасный режим. Для конкретного проверенного по SHA256 EPF/ERF передаётся штатное `ОписаниеЗащитыОтОпасныхДействий` без повторного интерактивного вопроса; глобальные настройки целевой базы не изменяются. Первая версия ограничивает EPF/ERF 1 MiB; большим обработкам нужен отдельный транспорт.

Ответ старта содержит `run_id`. Читать `edt_runtime_execute(action=status, run_id=...)`: успех — только `terminal=true`, `phase=completed`, `execution.success=true`. Успешный сценарий с ошибкой payload получает `phase=execution_failed`. Результат до 2 MiB. Повреждённый JSON, неверный request_id, не-boolean success или превышение лимита дают `phase=result_invalid`, `outcome_unknown=true` и сохраняют возможность отмены/уборки. Неподдерживаемое JSON-значение приводит к `RESULT_NOT_JSON_SERIALIZABLE`, а не зелёному успеху. Возвращаются текст/стек ошибки 1С и контекст выполнения.

Сценарий выполняется независимо от запросов агента. Через обычные debug-команды можно читать стек/переменные и продолжать остановленный сеанс. Исполнение кода открывает служебную форму VAExtension, затем закрывает её; это не операция без изменения текущего активного окна. Для проверки интерфейса продолжить отдельным сценарием Vanessa либо semantic UI и снимками.

## Повтор, отмена и уборка

Код и параметры проходят парсер Vanessa в Base64, поэтому `$...$`, inline-выражения и Unicode не подвергаются подстановке. Это транспортное кодирование.

Тот же ключ с тем же кодом/профилем возвращает существующий запуск. Потерянный вторичный индекс восстанавливается из сохранённого claim без повторного исполнения. Изменение аргументов с прежним ключом отклоняется. После прерванной отправки с неизвестным исходом автоматического повтора нет. `action=cancel` останавливает собственный управляемый запуск, но не обещает откат уже совершённых записей, внешних вызовов и фоновых заданий. `action=cleanup` после завершения удаляет исходный feature и JSON-результат, сохраняя tombstone ключа. Управляемый runner отдельно закрывает собственные клиент, менеджер и debug-сеанс. Служебные журналы Vanessa могут содержать исполненный код; секреты в code/parameters передавать не следует.

Разрешение на исполнение кода определяется поручением пользователя и выбранной базой. Команда не отключает права пользователя, безопасный режим EPF или глобальные защиты. Открытие произвольной формы EPF и UI-сценарии выполняются отдельными средствами Vanessa; `external` — вызов экспортной функции, а не её открытие.
