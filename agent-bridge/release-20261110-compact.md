# EDT Agent Bridge 1.4.0.20261110zzzzcompact1

Агент получает до десяти компактных MCP-входов вместо полного каталога схем.
Точный контракт нужной операции раскрывается по запросу через `edt.help`.
Все прежние команды и их аргументы сохранены, включая validation token и
ограничения доступа. Полный каталог доступен с `tools/list {"profile":"legacy"}`.

- `edt.run op=route` подбирает маршрут проверки: Native для кода/запросов/данных,
  прямой TestClient для поддерживаемого UI при доступном Python, Vanessa для
  сценариев и неподдерживаемых UI-действий. Это план: запуск, подготовка среды
  и изменения базы выполняются отдельными явными командами.
- Неизвестный исход операции блокирует переключение исполнителя и повтор записи.
- `edt_infobase_bind` привязывает существующую регистрацию EDT по UUID к текущему
  контексту проекта/ветки, включая файловые базы вне workspace/home. Preview/hash,
  явная замена основной базы и durable receipt защищают от случайной перепривязки
  и повторов. Пароли, платформа и ограничения путей connect_infobase сохраняются;
  конфигурация базы не обновляется и клиент не запускается.

Основное и независимое ревью не выявили подтверждённых P1/P2. Проверены
743 Java-теста, границы самостоятельного продукта и живой сценарий из 9 шагов
в собственной базе на 8.5.1.1522. Объявления схем в тестовом каталоге уменьшились
с 199750 до 5456 байт (97.3%); это размер JSON, а не замер токенов всей задачи.
Живое переключение основной регистрации по UUID прошло; первичная ассоциация
непривязанной регистрации отдельно покрыта контрактными тестами.

После обновления обновите каталог MCP в клиенте (при необходимости переподключите
интеграцию), чтобы агент увидел компактные входы. Пользовательская EDT и базы
при проверке не использовались. Собственные тестовые ресурсы убраны.
Native API ZIP и EPF этого релиза повторно использованы без изменения бинарников.
