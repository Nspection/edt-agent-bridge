## Проверка исправлений независимого ревью

В окончательной сборке fix1 повторно проверены внутренний native host, клиентский снимок+сервер42 и no-EPF cleanup. Поставляемая AgentHost.epf пересобрана штатной фабрикой/dumper EDT из актуального шаблона. Native ZIP protocol2 проверен контрактами; отдельный p2 verifyOnly пройден. Публичная проверка выполняется после публикации по обычному URL.

Для fault injection собран отдельный игнорируемый private probe из того же шаблона с тремя искусственными исключениями; исходный продуктовый шаблон восстановлен побайтно. Подтверждены: Complete отвергнут до принятия, Complete принят с потерянным ACK, сервер выполнил запись счётчика, но его ответ потерян. В первых двух случаях ошибочный пакет сохранил ровно два шага, третий не исполнился, следующее поставленное задание вернуло42. В RPC-случае счётчик остался1 после нескольких тиков, второй шаг не выполнился, результат terminal outcome_unknown. Тестовые точки не входят в релизные JAR/EPF.

При старте после перезапуска собственной EDT встретился штатный already_connected: ошибочный host ещё не запускал BSL. Incremental с маркером необходимого FULL корректно отказал. Native refresh, stop того же неуспешного host и повторный start восстановили разрешённый FULL; защитные маркеры вручную не менялись. Это остаётся диагностируемой особенностью native lifecycle, а не скрытым автоматическим повтором бизнес-операции.

Уборка повторного ревью завершена: четыре собственных host (включая известную частичную подготовку EPF), одноразовая ИБ и проект удалены; моя EDT закрыта, исходный bundles.info восстановлен побайтно. Единственный поздно пересозданный bin/EPF внешнего тестового проекта был сохранён защитой хешей, отдельно просмотрен и удалён в пределах собственного fixture. Продуктовая защита изменённых исходников не отключалась.
