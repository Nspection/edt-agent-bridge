# Следующий этап: подготовка зависимостей

Native реализован отдельным этапом 1.4.0.20261111zzzzzznative1: [настройки и MCP](native-package.md). Установка Python и подготовка Vanessa остаются следующими этапами.

- Native ZIP: автоматически загружать совместимый пакет после установки/обновления плагина, в фоновом задании вне UI. Проверять релизный manifest и SHA256, кешировать по версии/хешу, повторно не качать совпадающий пакет. Офлайн/ошибка не блокируют запуск EDT; видны состояние и повтор загрузки. Получение ZIP само не запускает 1С/EPF и не меняет доверие.
- Python: обнаруживать имеющийся совместимый CPython; при отсутствии получать официальный установщик поддерживаемой Windows x64 версии с проверкой подписи/хеша. Подготовка managed-окружения не меняет системный Python. Установка интерпретатора — явное действие в рамках разрешения пользователя; не включать большой installer в каждый p2 ZIP.
- Vanessa: подобрать совместимую версию и получить проверенный пакет, подготовить/проверить профиль и нужные для выбранного маршрута компоненты. Подготовка базы/расширений и защита платформы учитываются отдельно. Vanessa не нужна для Native и прямого TestClient.
- Кнопка настроек и MCP используют общий backend. ИИ обязательно получает доступ через существующий edt.run: status, получение/подготовка нужных пакетов, восстановление собственного окружения и диагностика/next_call. Названия действий уточнятся в контракте реализации.
- Агент может исправлять подтверждённую проблему в пределах выданного разрешения; чужие окружения/базы не заменяются. Неизвестный исход установки/запуска расследуется по исходной операции, без слепого повтора. При необходимости пользовательского действия возвращать конкретную причину.

Проверять в изолированной EDT/своих fixture; пользовательскую EDT/базы не использовать. Поставка Native ZIP и её lifecycle/MCP-статус реализованы; далее установка Python и подготовка Vanessa.
