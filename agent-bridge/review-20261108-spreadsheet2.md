# Ревью семантического табличного объединения

База ревью: 9312d61. Просмотрены все изменённые файлы, новые Java-классы, MCP-контракты, тесты, упаковка и графические ресурсы. Два независимых статических прохода выполнены разными агентами последовательно; оба затем проверили исправления своих замечаний.

## Исправлено

- Структурные семантические ключи имеют типы и префиксы длины: текст со знаками-разделителями не скрывает изменения локализованных строк.
- Ручной сдвиг строк/колонок блокирует координатное автослияние до явного решения.
- Изменения повторяющихся блоков неоднозначны даже при неизменившемся уникальном заголовке; отдельные регрессии покрывают строки и колонки.
- Решения конфликтов записываются вместе с XML в native-операции, а не отдельным шагом после неё.
- Сброс не закрывает и не уничтожает грязный черновик до успешной защищённой записи плана.
- MCP save_ui получает реальную ошибку сохранения без модального диалога; clean-состояние редактора не считается доказательством записи.
- Навигация без выделения: назад — последнее отличие, вперёд — первое.

Незакрытых замечаний двух независимых проходов нет. Их проверка статическая; сборку, native EDT-проверки и уборку выполнял основной агент.

Пределы: адаптер native compare SDK 28, Windows x64, EDT 2026.1.2.2 / JDK 17. Для другой SDK нужна повторная проверка. Изменения сложных списков и неоднозначной структуры требуют явного решения. Прикладная печать и исполнение конфигурации в 1С этим ревью не подтверждаются.
