# Native: ожидания, проверки и частичные результаты

Доступно с 1.4.0.20261112native3 через прежний edt_runtime_host и компактный edt.run. Отдельные MCP-инструменты не добавлены. Бинарник Native, его ABI, HTTP endpoint и таймауты WinHTTP сохранены. Новая обработка публикует host_features=["batch_controls_v1"]; для старого host используйте прежние шаги или подготовьте новый после разбора старых запросов. Новый host не отменяет уже выполненные изменения.

## Шаги

Каждый из 1..16 шагов сохраняет code/context/parameters/caption/screenshot. Новые поля:

| Поле | Поведение |
| --- | --- |
| kind=execute | Однократное исполнение, прежний режим по умолчанию |
| kind=wait | Явно повторяемая проверка Boolean до true или срока ожидания |
| kind=assert | Однократный Boolean; false и другой тип останавливают пакет |
| kind=read | Однократный код чтения и необязательная проекция select |
| timeout_ms | Только wait; 60000 по умолчанию, 1000..300000 |
| interval_ms | Только wait; 1000 по умолчанию, 1000..10000 |
| select | Только read, до 32 уникальных путей по JSON-результату |
| screenshot_on_failure | Снимок на следующем tick после ошибки, затем остановка |

Пример для разрешённого собственного host:

```json
{
  "action": "execute",
  "host_id": "<id>",
  "execution_mode": "batch",
  "idempotency_key": "form-probe-01",
  "steps": [
    {
      "kind": "wait",
      "code": "Результат = ЭтаФорма.Заголовок <> \"\";",
      "timeout_ms": 60000
    },
    {
      "kind": "assert",
      "code": "Результат = ЭтаФорма.Заголовок <> \"\";",
      "screenshot_on_failure": true
    },
    {
      "kind": "read",
      "code": "Результат = Новый Структура(\"title,name\", ЭтаФорма.Заголовок, ЭтаФорма.ИмяФормы);",
      "select": [
        "title"
      ],
      "screenshot": true
    }
  ]
}
```

В JSON примера BSL-кавычки должны быть экранированы. Параметры кода передаются через parameters/ПараметрыВызова без строковой подстановки. ЭтаФорма означает форму host. Для прикладной формы код должен явно получить проверенную ссылку на нужную форму: read не открывает формы и не угадывает активную форму. select выбирает из уже возвращённого JSON; пример rows.0.Code, индексы с нуля. Ответ — массив {path,value}; отсутствующий путь даёт selection_failed, существующий JSON null сохраняется. Сужайте и исходный код чтения: select не ограничивает работу BSL или запросов до сериализации.

wait — контракт вызывающего: code обязан быть проверкой без побочных эффектов. Плагин не может доказать чистоту произвольного BSL и не предоставляет песочницу. Только wait повторяет BSL. Ошибка выполнения прекращает ожидание, а не запускает бесконечный retry. Таймер отдаёт управление 1С между попытками. Карта может дорисовываться после готовности формы: задавайте относящееся к карте условие и проверяйте снимок.

Deadline проверяется до interval и после probe. Синхронный BSL/RPC невозможно прервать этим лимитом: поздний true возвращается как condition_timeout после завершения вызова. Это не отмена и не откат. Время отправки пакета, очередь и снимки не входят в timeout_ms конкретного wait; весь пакет может выполняться дольше. Во время паузы отладчика таймер не выполняется.

## Получение результата

execute возвращает request_id. action=result возвращает прежние terminal/state/execution и новый progress: sequence, phase, current_step, attempts, elapsed_ms при ожидании и value с подтверждёнными результатами шагов. При ожидании terminal=false. В терминальном ответе с execution массив progress.value не дублируется: вместо него progress.reported_steps; результаты находятся в execution.value. Progress сохраняется атомарно до подтверждения; повторяется только то же сообщение прогресса, а не исполнившийся шаг. Снимки также доступны отдельным snapshots до окончания пакета. Полученные записи шагов не изменяются при следующих progress-сообщениях. Потеря процесса/перезапуск не превращает progress в успешный итог: возвращается outcome_unknown с последним сохранённым progress.

Успех только terminal=true, state=completed, execution.success=true. Не повторяйте изменяющий пакет, если исход неизвестен; получайте первоначальный request_id. Старый ключ с изменёнными параметрами отклоняется. После обновления не пересобирайте старые команды ради чтения результата — используйте result.

Значения шага больше 16384 символов сериализованного JSON явно опускаются с value_omitted=true/value_limit_chars, не меняя известный успех исполнения. Ошибки ограничены 4096 символами с error_truncated/snapshot_error_truncated. Для получения данных используйте узкое read; не повторяйте изменения для повторного получения большого ответа. Количество шагов, общий payload и квоты снимков остаются прежними. Неудачный screenshot не удаляет результаты и не повторяет BSL; packet завершается failed. Сетка и линейки создаются после capture, оригинал сохраняется.

## Проверка и границы

Контракты проверяют sequence/prefix, отсутствие редоставки BSL, конфликтующие подтверждения, рестарт, отказ сохранения и повтор того же acknowledgement. Живая приёмка проводится только на собственной одноразовой базе 8.5: готовность через 32 секунды, UI-title/read/assert, таймауты, остановка зависимых шагов, снимки/сетка и сохранённый progress после stop. Это не проверка конкретной карты или форм TMS пользователя.
