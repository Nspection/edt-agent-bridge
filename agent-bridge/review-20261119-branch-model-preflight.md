# Проверка состава BM и XML перед обновлением 1С

На отдельной EDT 2026.1.2.2 и собственной файловой ИБ 1С 8.5.1.1522 проверена смена Git-веток. Сразу после checkout модель может отставать от файлов. Bridge ждёт завершения импорта, сравнивает состав и читает объекты в транзакции BM. При изменении модели во время проверки Bridge может повторить только диагностику. Для metadata-host проверка проходит также перед созданием временной обработки.

На корректной ветке инкрементальное обновление достигло EQUAL. Повторная привязка по UUID и первый FULL metadata-host также достигли EQUAL. На контрольной ветке, где Configuration.mdo по-прежнему ссылался на Enum.BranchEnum, а имя внутри MDO было подменено, инкремент и FULL остановились на source_preflight с точным FQN. После возврата на корректную ветку база осталась EQUAL.

Перед FULL Bridge строит отдельный контрольный экспорт SDK в формате выбранной платформы. На версиях новее 8.3.19 проверяется ZIP. Проверяются объявления и файлы, в том числе пути вложенных подсистем. Внутренним пакетом reloadInfobase управляет SDK, и штатный API обновления не предоставляет Bridge этот пакет.

На изолированной ветке с добавленной вложенной подсистемой контрольный ZIP прошёл проверку, а Конфигуратор отклонил внутренний пакет штатного FULL с отсутствующим TestChild.xml. Отказ возвращается как native_export_package_incomplete с путём и FQN. Это диагностика ошибки SDK после вызова обновления. Автоматического повтора нет.

Рабочие TMS_GIT и TMS_FILE85 в проверках не использовались.
