# Ревью разрешений динамического обновления

Основное и отдельное независимое ревью проверили полный diff относительно 5ea5c07: native-only кнопка/hash/ownership, once/task/persistent семантика, scope записи, CAS и отзыв, read после рестарта, exposure/mutation policy, FULL/EQUAL, работа без повторного load и файловые границы.

Подтверждён P2: scope записи был CURRENT, но NativeUpdateInteraction фиксировал только project name/UUID/target. Если pending update A переживал смену на B с тем же UUID/target, grant B мог принять окно A. Независимый real-store harness воспроизвёл проблему.

Исправление: исходные шесть полей захватываются до SDK-вызова; полный scope перепроверяется перед продолжением, persistent lookup требует original scope SHA. Для dynamic проверка повторяется на UI перед кнопкой; отмена не требует текущей привязки. Новый describeScope не делает workspace owner inventory/DB sync, модель не читается под file-store lock. Независимый повтор отверг drift A→B и B→A и принял только matching scope. Новых подтверждённых P1/P2 нет.

866 Java и 57 Python-контрактов прошли. Собственный финальный SDK-прогон: stale hash, FULL dynamic до EQUAL, grant текущему вопросу, future auto-answer, revoke поID и ожидание после отзыва. Кластер/несовместимые структурные изменения/обновление открытых форм не проверялись. Все данные и процессы принадлежали собственной fixture; пользовательская среда не менялась.

Managed Python fixture встретила LocalAppData/MSIX redirect до запуска клиента; native сценарии проверялись обычным собственным thin client. Перезапущенная private EDT сначала дала SDK already_connected: состояние/ошибка сохранены и reconciled отдельным FULL/reload до EQUAL. Факты и уборка описаны в dynamic-updates.md. Это не выдаётся за пройденный TestClient-прогон или за повтор неизвестной бизнес-операции.

Проверенные сценарии не закрывают чужие сеансы и не отключают ограничения 1С. Постоянное разрешение не является разрешением начать новое обновление; оно лишь отвечает на принадлежащий уже запущенной операции native-вопрос. Отзыв не откатывает уже начатую операцию. После merge проверяется эквивалентность пакета, после публикации — публичный p2.
