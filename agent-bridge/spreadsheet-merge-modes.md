# Режим объединения всего макета

Доступно с `1.4.0.20261109zmodes2`. В версии `zeditors1` этих режимов ещё нет.

В верхней панели табличного объединения доступно меню **«Объединение макета»**:

| Режим | Результат |
| --- | --- |
| Взять текущую конфигурацию (слева) | Целиком макет текущей конфигурации |
| Взять конфигурацию-источник (справа) | Целиком макет источника |
| Объединить с приоритетом текущей | Независимые изменения обеих сторон, в конфликтах свойств — текущее значение |
| Объединить с приоритетом источника | Независимые изменения обеих сторон, в конфликтах свойств — значение источника |

Режим относится ко всему макету. Выбор стороны под таблицей различий по-прежнему относится только к выбранному отличию. «Объединить независимые изменения» сохраняет ручные правки и оставляет конфликты; новый режим **пересчитывает результат из исходных сторон**, заменяя ручные правки и прежние решения после явного подтверждения. Пишется только native CUSTOM_MERGE план, исходники меняются позднее при штатном объединении EDT.

Приоритет не угадывает сдвиги строк/колонок: структурный конфликт остаётся нерешённым. Для полного выбора стороны использовать «Взять …». Без общего предка нельзя отличить удаление от добавления: спорные различия принимаются по выбранной стороне, трёхсторонняя семантика удаления не обещается. Не использовать приоритет как гарантию объединения всех уникальных строк без предка.

MCP использует тот же механизм:

```json
{"action":"merge_mode","session_id":"…","node_id":"…","mode":"PRIORITY_OTHER","replace_result":true,"expected_node_sha256":"свежий hash из read"}
```

Допустимые mode: MAIN, OTHER, PRIORITY_MAIN, PRIORITY_OTHER. replace_result=true обязателен; несохранённый визуальный черновик блокирует вызов. Ответ содержит mode, replaced_result, saved_to_plan, structural_conflict и число unresolved_conflicts. После операции перечитать результат и открыть/обновить UI; нерешённые конфликты блокируют применение.

Проверка: 6 новых regression tests для целой стороны, независимых свойств и конфликтов, отсутствующего предка, структурных сдвигов и неверного режима. В отдельной EDT 2026.1.2.2 проверены все четыре режима с общим предком, сохранение независимых ячеек и форматирования, подтверждение замены сохранённой ручной правки, отказ без replace_result и при устаревшем hash. Через native UI harness проверены открытие меню основной кнопкой и получение четырёх native пунктов, отмена подтверждения поверх несохранённой правки и применение всех четырёх режимов после подтверждения. MCP блокирует dirty-черновик. Физическая мышь не имитировалась; подтверждения обрабатывались только для собственных тестовых диалогов в отдельной EDT. PNG результата просмотрен. Исходные три макета не изменились. Три проекта, регистрации, снимки в workspace и временный каталог удалены; БД не создавались.

Основное и независимое read-only ревью завершены. Исправлено ленивое заполнение popup: MenuManager обновляется до показа, пункты доступны и при программном вызове. 585 Java-тестов, 29 PowerShell-контрактов и граница standalone-продукта прошли. Приватный тестовый probe удалён из конфигурации и не включён в сборку.
