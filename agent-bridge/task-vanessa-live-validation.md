# Приёмка task workflows на настоящей Vanessa — 09.11.2026

Релиз `1.4.0.20261109workflow9`. Первичная проверка после workflow8 выполнена на taskva4; после ревью полный цикл повторён на финальной сборке workflow9.

## Исправления

- Прогон файловой базы теперь сообщает канонический connection identity, как task binding. Ранее хеш пути без префикса отличался от хеша `file:...`, и отправленный шаг не удавалось прикрепить к сессии (`Run target differs`). Защита чужого проекта/приложения сохранена.
- Восстановление соединения после перезапуска больше не полагается на EDT `isConnected(project,base)`: в установленной 2026.1.2.2 этот метод проверяет только контейнер проекта. Если нет EQUAL, выполняется штатный connectInfobase именно для выбранной базы. Проверка EQUAL и проверки результата обновления не отключены; ошибки подключения не проглатываются. Исключение — точный штатный отказ «already connected» с подтверждённым SDK-стеком: он означает уже зарегистрированную, но изменённую базу. Другие ошибки пробрасываются.
- Добавлен необязательный manager_mcp_port в профиль и управляемый запуск. Только при явном задании стартует установленный client_mcp менеджера; порт строго 1..65535, без произвольных startup-команд. Сессия использует соответствующий endpoint. Старый режим без MCP-порта сохранён.

## Реальная проверка

Отдельная EDT 2026.1.2.2/Java 17, платформа 1С 8.3.27.2325, Vanessa 1.2.043.47 и client_mcp 0.6.6 в новой базе менеджера. Проекты и две файловые базы созданы/привязаны через native EDT, с disposable_test_base=true. Для запуска без UAC использована отдельная локальная копия платформы с собственной конфигурацией. Временное доверие ограничено точной базой менеджера; установленные системные настройки платформы не изменялись.

1. `edt_task_session(open)` закрепил проект, приложение и профиль. После перезапуска привязка проверена повторно.
2. `edt_task_step(tool=edt_check,action=call)` запустил настоящий сценарий; повтор с теми же аргументами вернул прежний run_id без второго клиента. После исправления подключения EDT подтвердил EQUAL, запустил отладку и Vanessa.
3. `edt_task_wait(kind=run)` вернул последовательность этапов и визуальный checkpoint. PNG реального TestClient просмотрен: открыт список AuditItems.
4. В том же TestClient через `edt_task_step(tool=edt_form_action)` открыта форма создания, введено TaskSessionVanessaLive, выполнена команда «Записать и закрыть». `kind=operation` подтвердил завершение; текстовое условие и ожидаемое окно проверены. Повтор ввода вернул прежний job_id.
5. `edt_task_wait(kind=form_change)` вернул delta формы, `kind=form` подтвердил условие; отсутствующее окно дало timed_out=true/postcondition_verified=false.
6. `edt_form_state(view=values)` прочитал сохранённую запись в списке с кодом 000000001. Затем подтверждён просмотр конкретного checkpoint по его ID/SHA256 и сценарий продолжен.
7. Настоящий JUnit: 1 тест, 0 ошибок. terminal=true/phase=completed, собственные менеджер и TestClient закрыты. Статус шага completed, scenario_sources_match=matched_at_checkpoints.
8. `edt_task_cleanup(preview/apply)` удалил зарегистрированные прогоны, импортированный диагностический снимок, базы, их регистрации/настройки и audit-проекты. Проверены all_tracked_resources_cleaned и закрытие обеих сессий. Старые диагностические отказы разобраны отдельно; неизвестный claim не пересылался автоматически.

572 Java-теста и 29 контрактов PowerShell-контроллера прошли. Первичные evidence: `.runs/task8-vanessa`; финальная повторная проверка и уборка: `.runs/task9-review/live.json`, логи, снимок и cleanup.json. Рабочая EDT/x5 не затрагивались. Тест не доказывает все обработчики x5, серверный кластер или 8.5; личность TestClient остаётся live_client_binding_verified=false по ограничению upstream API. В этом прогоне целевая база дополнительно сверена по строке соединения/ PID настоящей Vanessa.

## Повтор после независимого ревью

На workflow9 заново созданы два проекта и две одноразовые базы. Повторён сценарий с UI-действиями, сохранением записи, чтением значений, визуальным checkpoint и проверкой отпечатков. После завершения через EDT создан дополнительный общий модуль: перед вторым запуском штатный API показал `connected=true`, `equality=NOT_EQUAL`. Повторный edt_check обновил базу, запустил реальную Vanessa и завершился успешно. Оба прогона закрыли свои процессы; обе task-сессии очищены и закрыты. Временное правило доверия, копия платформы, базы, проекты и записи запуска удалены с отдельной проверкой.

Контракты отдельно проверяют занятый/чужой MCP-порт, сохранение RunId при ошибке готовности, остановку собственных процессов при неудачном старте, исключение точного native already-connected и строго ограниченное чтение старой файловой привязки.

При финальной уборке native AgentMode менеджера ещё удерживал каталог: первая попытка удаления безопасно отказала, файлы сохранились. После подтверждённой отвязки завершён только процесс с точным путём этой одноразовой базы и /AgentMode; получен новый cleanup-preview и уборка завершена через MCP. Это не подтверждение автоматической остановки всех служебных процессов EDT.
