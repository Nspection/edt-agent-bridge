# EDT Agent Bridge 1.4.0.20261108workflow5

Проще поручить агенту проверку изменения: одна команда даёт сводку проекта и базы, другая запускает готовый цикл обновления, отладки и Vanessa. Результат приходит кратко, подробности доступны по запросу.

- `edt_session_summary`: модель EDT, идентичность/синхронизация базы, отладчик и сохранённый профиль без запуска клиента.
- `edt_check`: start/status/cancel по сохранённому профилю; обновление базы выбирается явно.
- Новые события выдаются порциями; компактный ответ не копирует большие журналы и вложенные результаты. Старые status-команды сохраняют полную выдачу по умолчанию, добавлен compact=true.
- Для новых прогонов ключ запроса сохраняется через перезапуск EDT. Утрата снимка не вызывает слепой повтор.
- Исправлены курсор сохранённой истории, возможное смешение имени базы и её состояния, длинные ошибки и структурированный CurrentStep Vanessa.

Проверки: 462 Java-теста, 24 контракта контроллера, отдельная EDT/1С 8.3.27.2325, успешный сценарий с обновлением базы и просмотром снимка, ошибка сценария, отмена, повтор запроса после перезапуска и штатный p2 verify-only. Собственные тестовые проекты, базы и записи запуска убраны, временное правило доверия удалено. [Рабочий цикл и границы](quick-workflows.md).

Ссылка обновления EDT остаётся прежней: https://nspection.github.io/edt-agent-bridge/

Native host EPF/ZIP приложены для удобства; их код в этом выпуске не изменялся. Проверяйте SHA256 по приложенному манифесту.
