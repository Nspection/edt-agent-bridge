# Меню заголовка и системные диалоги

С `1.4.0.20261117uimenu1` прямой TestClient Windows поддерживает стандартное меню заголовка формы и закрытие распознанного диалога настройки формы/списка. Vanessa и Native host не исполняют эти действия. Доступность проверять по установленному контракту.

1. `edt_form_state`: `transport=testclient`, `client_id`, `view=menu`. Сохранить `snapshot_id`, точные `window.title` и `window.form_name`.
2. `edt_form_action`: `action=menu_open`, `ui_backend=window_message_click`, прежние `client_id/snapshot_id`, точные `expected_window/expected_form`, устойчивый `idempotency_key`. По умолчанию `capture=true`: результат содержит отдельный `native_capture` со снимком реального popup.
3. Читать `native_ui.items`: только видимые пункты верхнего уровня, их текст и доступность. Подменю не раскрываются; скрытый каталог стандартных команд не выдаётся за меню. `header_menu_proven=true` подтверждает наблюдение этого меню.
4. Для уже открытого меню новый `view=menu` возвращает `capture_call`; использовать его для изображения без повторного открытия. При исчезновении/замене popup снимок не считается доказанным.
5. `menu_close`, `ui_backend=window_message_close` с новым снимком и теми же точными guards закрывает только меню, открытое этим работником.

Backend открытия семантически находит кнопку меню через UI Automation, затем вычисляет её центр и отправляет одну пару оконных сообщений мыши в проверенный HWND. Это явный оконный backend с внутренними координатами. Он не принимает координаты/произвольные сообщения, не использует глобальную мышь и не активирует рабочий стол. Контролируется PID, время запуска, поток, владелец, UIA identity и геометрия. Смена состояния приводит к отказу, автоматического переключения backend или повторного нажатия нет.

## Закрытие настройки формы/списка

После успешной стандартной команды `ФормаИзменитьФорму` / настройки списка работник пытается привязать конкретный экземпляр диалога. Проверить `native_dialog_close.available=true`. Затем прочитать `view=system_dialog` и вызвать:

```json
{"transport":"testclient","client_id":"<owned client>","action":"system_dialog_close","ui_backend":"window_message_close","snapshot_id":"<fresh dialog snapshot>","expected_window":"Настройка формы","return_form":"<original form_name>","idempotency_key":"<stable close key>"}
```

Проверяются исходная форма, operation_id открывшей команды, TestClient window ID и нативная identity диалога. Одно совпадение заголовка не разрешает закрытие. Незнакомые диалоги, корневое окно клиента, предупреждения безопасности и подтверждения не поддерживаются этим действием. Используется запрос WM_CLOSE, без нажатия «Да», «ОК» или выбора сохранения/отбрасывания. Если платформа оставила окно/открыла подтверждение, результат закрытия не подтверждается. Успех требует возврата исходной формы.

Эти три действия выполняются отдельно; в `batch` не принимаются. Изменение состояния после отправки сохраняет `outcome_unknown` и mutation barrier. Исследовать исходную операцию, не обходить её новым ключом. Основная квитанция действия фиксируется до необязательного PNG: сбой снимка отражается в `native_capture` и не превращает уже завершённое нажатие в разрешение повторить его.

## Проверка

Проверяется в собственных минимальных конфигурациях на отдельном невидимом desktop Windows: 8.5.1.1522 и 8.3.27.2325. Пользовательские EDT, проекты x5 и базы не используются. Приёмка конкретного прикладного меню, произвольных подменю или всех типов системных окон не заявляется.


### Горизонтальная прокрутка таблицы TestClient

Получите свежий `snapshot_id` через `edt_form_state` с `transport=testclient` и `view=elements`.
Для перехода к колонке можно сразу получить её имя и снимок формы через `view=table` с именем `table`.
Без параметра `columns` эта команда возвращает список имён и заголовков колонок.
Вызовите `edt_form_action` с тем же `client_id`, `snapshot_id`, `expected_window`, `expected_form`,
точным именем `table` и новым `idempotency_key`.

- `action=table_scroll_horizontal` принимает `direction=left|right` (примерно на ширину видимой области)
  или `horizontal_percent` от 0 до 100. Ответ содержит подтверждённое положение до и после.
- `action=table_reveal_column` принимает `column`, точное имя элемента колонки. Если колонка уже видна,
  операция подтверждает это без ввода. Для колонки шире видимой области проверяется показ её центральной области.

Команды выполняются отдельно от batch. Поддерживается одна видимая таблица с распознаваемыми колонками
в управляемой форме собственного клиента Windows. Bridge связывает имена TestClient с наблюдаемой геометрией
и перемещает штатную полосу 1С. Когда цель или полоса неоднозначна, Bridge возвращает причину отказа.
