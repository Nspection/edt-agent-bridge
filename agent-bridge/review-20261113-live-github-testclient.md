# Ревью и живая приёмка reports3

Собственное ревью проверило разделение preflight/claim/POST, отзыв policy во время credentials, закрепление account и workspace, отсутствие секретов в MCP/пакете, сохранение unknown и дедупликацию. Исторический runtime после cleanup заменён проекцией подтверждённых cleanup receipts, без ложного отключения borrowed ресурсов. При живом resume обнаружена и удалена устаревшая причина ожидания согласия.

Независимое ревью Astra medium нашло потерю фактических worker enum и неполную инструкцию миграции GCM. Добавлены все пять failure_kind worker, completed_or_failed, вложенный protocol_rejection.status_code и регрессия раздельной identity разных причин. Инструкция поясняет scoped namespace, повторный connect и новую подготовку черновиков `prepared`; неизвестные отправки требуют только reconcile. Подтверждённых открытых блокеров нет при прохождении финальных обязательных проверок.

Живые доказательства: OAuth GCM в собственной EDT, POST через реальный MCP и независимый GitHub GET для Issue35, запрет до подтверждения, повторный submit без второго Issue и закрытие теста. Production service login/approve вызывался непоставляемым OSGi harness; SWT-интерфейс физически не нажат. Проверены thin client 8.3.27.2325, уникальный table_select, ФормаНайти с отдельным fresh form observation, ввод и Cancel. Command ACK сам по себе не трактуется как проверенное открытие формы. Отдельно подтверждены preparation cleanup connected=false и удаление owned disposable базы.

Финальные артефакты связаны с живой приёмкой равенством 25 class/resource hashes. После прогона дополнены только allowlist enum и очистка устаревшего reason при resume; эти изменения проверены детерминированными регрессиями, не объявляются повторной живой проверкой финальных bytes. Полный повторный построчный аудит старого проекта не заявляется; это ревью изменений и перечисленных жалоб. Пользовательская EDT/базы и x5 не затрагивались.
