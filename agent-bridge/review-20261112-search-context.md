# Ревью и приёмка поиска/контекста

Версия1.4.0.20261112zzzzzcontext1. Собственное и независимое ревью кода: открытых подтверждённых P1/P2 нет. Независимые harness проверили Unicode/dotted routing, legacy opt-in, границы budget/surrogate, prevalidation до чтений, небезопасные пути, ambiguous candidates, frozen job plan, исходный job в next_call, переполнение bounded очереди и независимость обычной/search очередей. Счётчик сотен тысяч символьных boundary assertions не выдаётся за число отдельных JUnit-тестов.

Полный Java-набор:1050 тестов и standalone boundary. Исходники привязаны к сохранённым SHA256. Native/TestClient runtime не менялся;33 отобранных runtime-класса побайтно совпали с предыдущим релизом. Это проверка неизменности выбранных классов, не повторная приёмка всех runtime-сценариев.

Legacy acceptance: реальный SearchInCodeTool предыдущего релиза против нового в отдельных собственных OSGi workspaces.18 полных JSON-сравнений: text/regex, all/modules/queries, идентификатор/фраза/Unicode, более500 совпадений и несколько файлов; omission=text отдельно. Проверены auto literal top_k/has_more, auto BM25 и безопасное Unicode-усечение snippet.

Semantic acceptance: создана собственная конфигурация через EDT project manager, без регистрации/запуска ИБ; настоящий ManagedApplicationModule.bsl прочитан через BslSemanticService. Batch сопоставлен с одиночными text/startLine, ошибка одного метода не скрывает другой. В SDK OSGi resource-set provider недоступен, существующий сервис переходит к standalone Xtext fallback после30с ожидания на чтение. Это не ускорение семантического парсера и не ошибка, внесённая batch. Финальный безоконный OSGi/EDT прогон проверяет terminal=false→исходный job→результат;Время ожиданий такого SDK runtime не подменяется временем file-backed benchmark.

Private harness до успешного прогона исправлялся: Java module opens для Ignite, кодировка UTF8 в скрипте, подготовка каталога модуля, достаточный общий timeout. Промежуточная неполная GUI-оболочка дала ошибку штатного AI ChatView и не считается приёмкой пользовательского интерфейса; финальная проверка выполняется без окна. Отсутствие GUI не объявляется причиной ожидания resource-set provider. Эти ошибки фикстуры не объявляются дефектами продукта. Замечание независимого ревью к методике устранено разделением фактической routing-оценки и fixed-selection чтения; бесплатное разрешение методов из literal hits не учитывается как реальный выигрыш агента.

[Сравнение и ограничения](benchmark-20261112-search-context.md). Пользовательские вопросы/код TMS не публикуются. Пользовательские EDT/базы не использовались; свои источники/workspaces/configurations/probe и профили p2 убираются отдельно. Обычная ссылка EDT проверяется скачиванием SHA256 и p2 verifyOnly на собственной копии профиля. Доказательства: .runs/release-search-context/.
