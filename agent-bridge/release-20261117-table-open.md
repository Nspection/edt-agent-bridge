# EDT Agent Bridge 1.4.0.20261117table1

Добавлено типизированное `edt_form_action(transport=testclient, action=table_open)`, также в batch и шагах `edt_ui_run`. Для Table в `edt_form_state(view=elements)` доступны type-level potential_actions table_read/table_select/table_open.

Нужны свежий snapshot_id, точные expected_window и expected_form исходной формы, имя table, уникальный row_match и отличающийся точный target_form. Перед активацией заново проверяются исходная форма, текущий полный descriptor и критерии строки; неоднозначное/неподтверждённое совпадение не активируется. Штатный CHOOSE_ROW отправляется ровно одной парой action+commit. Успех требует изменившейся identity формы и совпадения target_form; expect.fields/window дополнительно проверяют карточку. target_form подтверждает тип/экземпляр формы, а не UUID записи: для проверки выбранной записи задавайте expect.fields.

Это штатная активация строки, не read-only получение ссылки и не гарантия open-only: в форме выбора она может выбрать значение/закрыть окно, обработчики приложения могут выполняться. Проверяйте точную исходную форму; не используйте форму выбора, если требуется карточка. data_changed не объявляется false для успешной активации. Координат, клавиш, подстановки ссылок из отображаемых значений и fallback не добавлено.

Потерянный ответ или неподтверждённая целевая форма сохраняют outcome_unknown/mutation barrier. Повтор того же idempotency_key читает durable result, а не повторяет UI. Чтение/status/result и stop/cleanup остаются доступны по прежним правилам.

Также исправлена обработка завершённого GOTO_ROW status12/value_not_found при проверке уникальности (включая table_select): это известный промах поиска, не ошибка незавершённого обмена. Нормализация ограничена критериальным GOTO_ROW; source guard сохраняется. Другие статусы, CHOOSE_ROW и таймауты не скрываются.

Проверено на собственной disposable базе8.5.1.1522: существующие строки/поля, durable result, отсутствующая строка, неверная цель/barrier и полный ui_run. Это не подтверждение live-работы на8.3 или произвольных обработчиков/иерархических таблиц. Native DLL/EPF не менялись. Пользовательские EDT, процессы, x5 и базы не использовались.
