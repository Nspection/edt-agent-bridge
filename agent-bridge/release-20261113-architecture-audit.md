# EDT Agent Bridge 1.4.0.20261113audit2

Исправления повторного независимого архитектурного аудита.

- Вложенные task-команды проверяют текущую MCP-политику до claim и при последующих вызовах, включая status/wait/batch. Отклонённый до claim шаг не расходует ключ.
- Native использует единый durable store: резервирование ключа предшествует публикации запроса, чтение по ключу и UUID проверяет одну запись. Потеря квитанции, индекса или полной истории блокирует повтор. Признак первой инициализации хранится в host.json.
- Старые Native-журналы доступны для чтения существующих квитанций. Для новых запросов требуется новый host; неизвестный исход нельзя обходить новым ключом или host.
- Refresh сохраняет awaiting_consent и продолжает только запуск того же нового host после точного согласия. Очистка и создание не повторяются.
- Проверка отсутствия временной обработки через существующий verifier использует общий gate исполнения; отзыв согласия блокирует новый запрос.
- HTTP не удерживает монитор сессии при долгой работе и записи ответа. Активные запросы защищены от TTL; DELETE прекращает допуск новых запросов, а trace закрывается после завершения уже принятых.
- Pages требует JAR текущей версии, проверяет p2-метаданные и публикует staging только из разрешённого проверенного инвентаря. Случайные файлы checkout не публикуются.
- Удалены приватные GSD-заглушки и недостижимая ветвь. Публичные совместимые методы сохранены.
- Убрано постоянное исчерпание согласий после 256 scope; записи имеют индивидуальную проверку размера и идентичности, без полного сканирования каталога при выдаче.

Проверки и ограничения фиксируются в review-20261113-architecture-audit.md и локальных квитанциях .runs/audit2. Пользовательская EDT и базы не являются целями проверки. Ускорение полного задания и экономия модельных токенов не заявляются без сопоставимого замера.

## Новые жалобы TestClient

`table_select` использует native поиск с проверкой однозначности без массового выделения строк. Проверка направления и текущего выделения совместима с 8.3.27; неподтверждённая уникальность возвращает `row_uniqueness_unproven`. Для 8.5.1 сохранён полный fallback, который подтверждает и заново читает выделенную строку. Ввод данных не выполняется при неоднозначности.

Отказы RPC сохраняют числовой status и публичные code/message из фиксированного словаря, а диагностика — имя метода без frame/target/значений. Неизвестный исход и запрет новых действий сохраняются, даже если чтение канала работает. Причина функционального отказа таблицы сохраняется в compact/batch summary и не затирается ожиданием постусловия.

У старого клиента нет API `DESELECT_ALL_ROWS` и `GET_CURRENT_ROW` версии 8.5.1. Поэтому полные `table_read/table_add/table_set` и current-row `table_describe` на 8.3 явно отклоняются до изменяющего RPC; они не объявлены поддержанными этим выпуском. Для одиночного выбора строки используется новый native путь. Причина исторического `ФормаНайти` без записанного status не восстановлена; выпуск делает последующие отказы диагностируемыми, а доступность прикладной команды зависит от состояния формы.
