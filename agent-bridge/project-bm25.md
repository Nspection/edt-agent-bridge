# BM25 по сохранённым исходникам проекта

С 1.4.0.20261112zzzzbm251 доступен дополнительный searchType=bm25 у прежнего edt_search_in_code. Компактные входы не добавляются; text (по умолчанию) и regex сохраняют прежний формат и порядок результатов. BM25 — лексическое ранжирование, не embeddings и не понимание бизнес-смысла без общих терминов.

## Вызов и выбор маршрута

Сначала edt.help с action=contract, op=edt_search_in_code. Далее вернуть аргументы в указанном entry (обычно edt.search):

```json
{"op":"edt_search_in_code","args":{"projectName":"MyProject","query":"проверка доступности склада","searchType":"bm25","scope":"modules","top_k":5}}
```

Точное имя/подстрока/шаблон — text/regex. Поиск аналогов по нескольким предметным словам — bm25. scope=modules включает BSL, all добавляет mdo и отдельные query/sdbl, queries сохраняет прежний фильтр расширений/пути query. Поля top_k (1–20, default 5) и rebuild применимы только к BM25. Query: 1–1000 символов, до32 нормализованных терминов. Пустой/некорректный запрос отклоняется до фонового задания.

Первое построение большого индекса может занимать десятки секунд. Работа выполняется в отдельной bounded-очереди с одним worker вне SWT UI, отдельно от общих jobs, обновления базы и UI-прогонов. Вызов ждёт до20с; если ещё не завершён, terminal=false/state=indexing/job_id и next_call ведут к edt_operation_status исходного задания. Следовать готовому вызову, не повторять поиск ради опроса. DONE содержит результат поиска; FAILED — ошибку, не пустую успешную выдачу. Задание/его результат ограничены обычным сроком хранения registry. Новый самостоятельный поиск после завершения заново проверяет сохранённые файлы.

## Что индексируется и как ранжируется

BSL разбивается по процедурам/функциям; декларации внутри строк и комментариев не создают методы. Вне методов остаются отдельные module-фрагменты. Английские и русские ключевые слова, UTF-8 BOM и CRLF поддержаны. Заголовок документа включает путь/имя объекта, имя метода, синонимы и комментарии основного mdo объекта. Для mdo индексируются выбранные текстовые поля synonym/comment/description, не произвольные реквизиты XML и не весь экспорт базы.

Токенизация учитывает Unicode, кириллицу, CamelCase, snake_case и ё/е; лёгкая нормализация русских окончаний помогает «склад/склада», но не заменяет морфологический/семантический анализ. BM25 использует k1=1.5, b=0.75; вес токенов заголовка3, тела/комментариев1. Сумма совпадений ранжирует документы, а не доказывает соответствие бизнес-требованию. scores не являются вероятностью. При равенстве — стабильный порядок пути/строки.

Выдача: file_path относительно проекта (включая src/), file_uri, method/kind, line декларации, start_line/end_line, matched_terms, snippet_start_line и фрагмент до6 строк/1200 символов. method ограничен256 символами; method_name_truncated явно отмечает ограничение. Для правки/вызова метода сначала прочитать исходный метод по точному пути/строкам, не использовать усечённое имя как полное. Совпадение может приходиться на имя/путь/синоним, поэтому фрагмент тела не обязан содержать все слова запроса.

## Актуальность и границы полноты

Индекс хранится только в памяти процесса, максимум два проекта в LRU. После перезапуска первый поиск снова строит индекс. У каждой проверки перечитывается список saved src и size/mtime/fileKey; содержимое перечитывается для изменённых файлов, зависимых от изменённого mdo модулей и при смене Git-контекста. Удаления/переименования убирают старые документы. Поддержаны обычный .git, detached HEAD, packed refs и linked worktree gitdir/commondir. Неизвестный контекст приводит к консервативной переиндексации.

Перед выдачей каждого файла проверяется SHA256 и положение фрагмента. Изменение во время чтения даёт один автоматический read-only rebuild/retry, затем явный отказ при продолжающихся изменениях. Полный rebuild очищает старый словарь; при фрагментации словаря возможна однократная компактизация. Никакой изменяющий код не исполняется повторно.

index.freshness=file_metadata_checked, returned_files_verification=sha256, atomic_project_snapshot=false. Это НЕ атомарный снимок всего проекта: несохранённые редакторы не включаются; намеренное изменение непрочитанного файла с сохранением всех метаданных может требовать rebuild=true. Код и ссылки на файлы сверять перед правкой. fingerprint относится к сохранённому корпусу/контексту, не подтверждает запуск/приёмку 1С.

partial/skipped_files/truncated_documents явно показывают неполноту. Один документ ограничен12000 токенами/2048 уникальными термами; отсутствие результата тогда не доказывает отсутствия реализации. Внешние src symlinks/linked источники не индексируются: распознанные ссылки пропускаются, защита пути также может вернуть явный отказ. Скрытые каталоги и посторонние файлы исключены; файлы более8MiB пропускаются. Квоты: 30000 файлов/256MiB исходников, 150000 документов, 300000 терминов, 8млн postings и оценка индекса до192MiB на проект. Превышение общих квот — явная ошибка. estimated_bytes — инженерная оценка структуры, не точное измерение heap; временные объекты и JVM также используют память.

Нет облачных запросов, скачивания модели, Python или отдельного сервера. Поиск не запускает/не обновляет базу, не меняет исходники, привязки, debug-порт и пользовательские настройки EDT.

## Сравнение и проверка

Сравнение проводится на отдельной зафиксированной копии TMS, по вопросам и ожидаемым методам, составленным независимым ревьюером до просмотра выдачи. Проверяются и цельная фраза, и сильный обычный OR-regex по отдельно заданным словам. Для baseline сохраняется прежний порядок выдачи/ограничение и производится дедупликация по методу до Hit@5. Это сравнение с одним обычным запросом, а не с лучшим многошаговым поиском агента.

Разметка содержит известные положительные примеры, не все релевантные места: считать Hit@5/MRR, не precision/nDCG и не универсальную полноту. Объём сравнивается на сопоставимых JSON-структурах без транспортной оболочки; это не точные токены и не стоимость модели. Метрики/ограничения конкретного прогона — в релизной приёмке. Сами вопросы, пользовательские фрагменты и копия TMS в публичный репозиторий не включаются.
