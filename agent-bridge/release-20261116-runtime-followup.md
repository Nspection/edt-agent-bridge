# EDT Agent Bridge 1.4.0.20261116reports2

- GitHub: вход через браузер или защищённый ввод токена, сохранённый аккаунт и точное SWT-подтверждение отправки багов и предложений. Отменённый вход сохраняет прежние credentials. Отказ GitHub сохраняет черновик для нового просмотра; повреждённый отчёт блокируется отдельно, без повторной отправки.
- MCP HTTP: ограниченная нагрузка до четырёх тяжёлых запросов без очереди; лишние запросы получают JSON-RPC `-32001` / `server_busy` до исполнения. Статус и ping доступны отдельно. Неподдержанный GET SSE не создаёт фоновые потоки; POST SSE сохранён. Метрики различают выполнение и доставку ответа.
- Формы: чтение и безопасный patch `extInfo` групп в inspect/mutate/recipe, включая карточки 8.5. Валидация отклоняет неизвестные свойства, неверные Boolean и конфликтующие имена. ID существующих элементов сохраняются; адресный экспорт формы сохраняет исходники владельца и Configuration.
- Обновление ИБ: внешний исходник проходит импорт BM и derived computations до проверки EQUAL и обновления. При timeout операция с ИБ не начинается; status не сканирует проект.
- TestClient: актуальный статус транспорта, отдельная диагностика первой readonly RPC и различение отказа до исполнения от неизвестного исхода. Защита повторного изменения при неизвестном исходе сохранена.
- Native: асинхронный снимок оставляет таймеру 1С возможность рисовать модальное окно. Исправлены прозрачные края, исчезающие popup и устаревшие кадры после смены канала. Один renderer на процесс; зависший захват запрещает новые до остановки процесса.

Непечатаемые пассивные тени исключаются с `capture_complete=false` и счётчиком, обязательный popup и основное окно не исключаются. Снимок требует осмотра, он не доказывает правильность бизнес-действия. Платформенное доверие к EPF/Native остаётся отдельным решением 1С; защита не отключается.

Проверки выполнялись только в собственной изолированной EDT и одноразовой базе. Сценарий исходной TMS с table_select/ФормаНайти не воспроизведён на пользовательских данных; улучшения диагностики и ограничений времени не являются доказательством устранения любой причины OperationError.
