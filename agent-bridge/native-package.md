# Автоподготовка Native-компоненты

С 1.4.0.20261111zzzzzznative1 при запуске EDT (включая первый запуск после установки/обновления плагина) фоновое задание получает совместимый Native ZIP. По умолчанию включено. Кеш проверяется по SHA256; совпадающий пакет повторно не скачивается. Это загрузка файла, без запуска 1С, изменения базы и доверия платформы.

Версия и SHA256 ZIP/DLL закреплены внутри плагина. Пакет берётся из конкретного официального GitHub Release, HTTPS-переходы ограничены GitHub/CDN. Проверяются manifest, Windows x64, состав и размер ZIP. Пакет с несовпадающими хешами не используется. Изменённый кеш сохраняется отдельно при восстановлении; его объём ограничен. Обрыв/офлайн оставляет возможность безопасного повтора, EDT продолжает работать.

В настройках подключения MCP: секция «Компонента Native», флажок автоматического получения, состояние и кнопка «Подготовить / повторить загрузку». Сеть и проверка кеша выполняются вне потока интерфейса. Кеш находится в workspace/.metadata/.plugins/com.codepilot1c.core/native-package; это общая зависимость workspace, она не удаляется вместе с отдельным host.

Через edt.run использовать op=edt_runtime_host:

```json
{"op":"edt_runtime_host","args":{"action":"package_status"}}
{"op":"edt_runtime_host","args":{"action":"prepare_package"}}
{"op":"edt_runtime_host","args":{"action":"configure_package","automatic_download":true}}
```

prepare_package возвращает job_id/next_call, параллельные запросы используют исходное задание. Готовность подтверждается package_status.ready=true, свежей проверкой файла. last_attempt — история последней фоновой попытки, не самостоятельное подтверждение готовности. При ошибке возвращаются безопасная причина и next_call для повтора; URL с параметрами и секреты в ответ не попадают.

Отключение автоматики запрещает фоновую загрузку при следующем запуске. Явная подготовка MCP/кнопкой и необходимость пакета при разрешённом запуске Native остаются доступны. Начатую загрузку настройка не отменяет; остановка плагина завершает lifecycle.

Для edt_runtime_host prepare и единой prepare intent=code можно не передавать native_path/expected_native_sha256: общий сервис получит и проверит пакет. Оба аргумента вместе сохраняют явный пользовательский вариант; один без второго отклоняется.

Сама обработка также нужна: шаблон входит в плагин, EDT создаёт/собирает EPF либо внутреннюю обработку согласно выбранному режиму. Отдельно скачивать её для штатного host не требуется. Получение ZIP не снимает запросы доверия EPF/бинарным файлам и не даёт разрешение обновлять базу. Python и Vanessa этим этапом не устанавливаются.
