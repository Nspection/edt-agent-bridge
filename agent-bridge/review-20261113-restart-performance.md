# Ревью restart1 и границы приёмки

Собственное и независимое Astra medium ревью проверили разделение активных ресурсов и истории, монотонность cleaned, сохранение изменённых файлов, общий порядок lifecycle/client locks, готовность Python и невозможность использовать candidate как доказательство доверия, generation ownership SWT callback, Native deadline/delivery/exit и запрет автоматического повторения неизвестной операции.

Исправления по ревью: candidate принимается маршрутизатором, history не участвует в проверке использования Python, архивирование выполняется вне глобальной launch-блокировки, ID проверяется до таблицы locks, повторный cleanup не меняет архив, journal под client lock заново проверяет cleaned перед созданием operations. Native status синхронизирован с launch/stop, необратимое закрытие выполняется только для известного завершённого Process; неподтверждённая идентичность лишь блокирует новую отправку. Успешный hello навсегда закрывает startup scope этой сессии. Сбой сохранения выхода повторно расследуется на исходном request_id; compact сохраняет причину отмены и not_dispatched. Новых подтверждённых блокеров в финальном статическом ревью не найдено; выпуск обусловлен успешными проверками точных bytes.

1256 Java, 179 Python, 33 controller +3 CLI +13 startup PowerShell проверок, OSGi/boundary/provenance и p2 verifyOnly на копии профиля. HTTP-тесты Native используют реальный loopback endpoint и подконтрольные hello/poll/result/часы; это не новый прогон 1С Native. Сохранены original request_id/key, progress и fail-closed правила при повреждении журнала. Таймер проверен на 1000 stop/start при ещё не выполненной отмене.

Живая проверка на опубликованных предыдущих bytes и финальном кандидате выполнялась в собственных изолированных EDT без запуска ИБ. Отдельно проверены actual route→testclient с candidate/verification_required и чтение cleaned клиента. Серия запуска/выхода на новом малом workspace с 18 собственными очищенными квитанциями описана ниже. Измеряется готовность UI heartbeat и roundtrip MCP, не время пользовательского клика и не полная готовность большого проекта.

Один выход из большого собственного workspace начался во время полной сборки TMS_TEST_AGENT и не завершился в установленный срок. Дамп показал CustomXtextBuilder.fullBuild, BSL reference resolver/BM и ожидающий Workspace.save; кадров com.codepilot1c и Java deadlock в нём нет. После фиксации стека остановлен только подтверждённый собственный PID. Такой выход не засчитан как успешный и не смешан с малой контрольной серией. Кто инициировал сборку, из снимка не установлено. Штатный выход большого проекта после завершения full build и длительный soak остаются непроверенными; эти исправления не объявляются доказанным устранением любого зависания до перезагрузки ПК.

Пользовательская EDT, базы, x5, настройки защиты и credentials не изменялись. Историческое удаление Касперским не объявляется false positive.
