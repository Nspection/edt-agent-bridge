# Проверка следующего workflow

Релиз: `1.4.0.20261109zworkflow10`, EDT 2026.1.2.2 / Java 17 / Windows, платформа 1С 8.3.27.2325.

- 620 регрессионных тестов прошли; проверена граница standalone-продукта. В production JAR нет тестового probe, старого чата/LLM-механизмов и OAuth.
- В отдельной EDT создана конфигурация с тестовым справочником и две одноразовые файловые базы. Настоящая Vanessa открыла список. Проверка профиля/PID/времени старта/реального соединения подтвердила правильный клиент и отклонила базу другого проекта. Привязанные UI-шаги открыли элемент, заполнили и сохранили запись, проверили значение и возврат к списку; сценарий завершился без ошибок, собственные manager/client закрыты.
- Подтверждены неизменный request/job при повторе, точная дельта реальной формы, обычное ожидание и отрицательный timeout. Порядок, дубликаты и неполные страницы дельты дополнительно проверены тестами.
- Реальная native EPF/компонента выполнила единый пакет проверки числа, количества строк, булева значения и NULL. Проверены отрицательные ожидания типа, ошибочный запрос и интеграция с task-step. Для старта этого тестового host использован строго локальный probe в приватной EDT с копией платформы: обычный launcher в этом окружении получил CreateProcess error=5. Probe запускал реальную EPF/канал; сами assertions шли через production MCP. Это не новая проверка обычного launcher на всех окружениях.
- Native-план табличного объединения с приоритетом источника и ручной правкой сохранён, затем восстановлен в новом сравнении после настоящего перезапуска EDT. Проверены отказы по отсутствию согласия, устаревшему hash, checksum и изменению источников. Проверка сохранности исходников выполнена до отдельного намеренного изменения собственного фикстурного проекта. Native BSL checkpoints не получили отдельной живой приёмки в этой итерации; вопрос ИИ дополнительно сохранён и восстановлен в финальной проверке.
- Обнаруженные ошибки исправлены: группировка PID Vanessa; отсутствие Java process arguments на Windows; разные виртуализованные пути к одному exe; отображаемое имя native enum; технические узлы с известным FQN и одинаковые свойства у разных родителей; NULL при JSON-сериализации; неполная страница дельты.

Уборка подтверждена: 2 базы, 5 audit-проектов, внешний host-проект, их startup/EDT-регистрации, собственная копия платформы, controller, probe и два временных правила доверия удалены. Остальные настройки сохранены. Старые прерванные прогоны не удалось убрать общим task-cleanup из-за отказа запуска helper; их ресурсы удалены отдельными native-командами после проверки процессов. Эти прогоны не были ложно помечены успешными.

Ограничения: локальная Windows-корреляция клиента; недоступный/удалённый/Web-клиент остаётся неподтверждённым. Checkpoint не переносит явный пользовательский порядок подчинённых объектов и неподдерживаемые custom settings — операция отказывает. Restore не применяет исходники и требует проверки плана, в том числе после ошибки. Результаты assertions не переисполняются тем же ключом после изменения данных.

После независимого ревью повторно подтверждены restore → native apply после перезапуска, фактическая запись ручного результата в MAIN и сохранность OTHER/предка. Новое сравнение начинает с пустыми отметками и вопросами, без автоподстановки checkpoint. NULL literal/параметр/ожидание прошли через настоящий task-step и native 1С; отрицательный отчёт сохранил explicit null. Дополнительная база, четыре audit-проекта, внешний host-проект, копия платформы, probe, регистрации и доверие также удалены. См. [финальное ревью](review-20261109-workflow10.md).
