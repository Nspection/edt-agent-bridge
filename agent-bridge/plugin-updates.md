# Проверка и установка обновлений плагина

Доступно с релиза `1.4.0.20261111zzupdates1`. Проверять установленную версию плагина в настройках EDT Agent Bridge.

В «Окно → Настройки → EDT Agent Bridge», рядом с настройками MCP, добавлен раздел «Обновление плагина»:

- установленная версия и результат последней проверки;
- «Проверить обновления» — немедленная проверка, в том числе при отключённой автоматической проверке;
- «Обновить плагин…» — подготовка обновления только Bridge из официального p2-репозитория и открытие штатного мастера;
- флажок «Проверять после запуска EDT и раз в сутки», включённый по умолчанию.

После каждого запуска EDT проверка начинается с задержкой 60 секунд, независимо от предыдущей проверки до перезапуска. При непрерывной работе повторяется раз в 24 часа. Настройка сохраняется через «Применить» / «Применить и закрыть». Изменение только параметров обновления не перезапускает MCP-сервер.

Фоновая проверка читает небольшой release-manifest.json по фиксированному HTTPS-адресу. Проверяются продукт, ограничение размера и OSGi-версия. Ссылки из ответа не используются как адрес установки. Проверка имеет сетевые таймауты; ошибка отображается в состоянии настроек без модального окна. При новой версии появляется ненавязчивое окно с кнопками «Обновить плагин…» и «Позже». Одна версия уведомляется один раз; ручная проверка остаётся доступной.

Установка не выполняется автоматически. По явному нажатию кнопки native p2 рассчитывает план в фоне, затем показывает стандартный мастер. Выбран только root `com.codepilot1c.feature.feature.group`; зависимости проверяет p2. Другие продукты не выбираются для обновления. Понижение относительно текущего bundle и уже установленного root не предлагается. Вручную скопированные bundles без соответствующего p2-профиля сопровождаются объяснением, как установить Bridge штатным способом. Ошибка доступа к профилю не приводит к ручному переписыванию файлов EDT.

Пользователь подтверждает установку, доверие/подписи и предложенный p2 перезапуск в штатном интерфейсе. Кнопки не меняют базу, не собирают проект и не останавливают пользовательские процессы.

## Проверка

Автоматические проверки охватывают сравнение версий, отказ от понижения, неправильный/большой manifest, фиксированный адрес, отключение/периодичность, уведомление один раз и выбор только Bridge root. Живая проверка проводится в собственной отдельной EDT; её результаты фиксируются отдельно. Само разрешение p2-плана не является выполненной установкой.


## Результат релизной проверки

Релизная сборка: 857 Java-тестов, 41 worker- и 16 table-контрактов прошли; standalone boundary проверена. Дополнительный временный SWT-probe в собственной EDT подтвердил наличие обеих кнопок и флажка, ручную проверку при отключённой автоматической, сохранение того же MCP-server object при сохранении настроек, проверку после перезапуска при недавнем lastAttempt, планирование через 86400000 мс и исполнение суточной проверки. Таймер был ускорен только в probe; startup-delay продукта остаётся 60 секунд.

На отдельной копии своего p2-профиля native ProvisioningUI рассчитал план старого Bridge до публичной версии `1.4.0.20261111zlockdebug1`, выбран только Bridge root. Для запущенного более нового bundle понижение не предлагается. Новый пакет проходит p2 director verifyOnly в собственной копии профиля с private destination. Установка и завершение мастера не выполнялись.

Синтетическая новая версия вызвала собственное уведомление: проверены флаги nonmodal/NO_FOCUS, кнопка обновления и отсутствие второго окна для той же версии. Это функциональная проверка SWT; окно было размещено за пределами экрана, пиксельная визуальная приёмка не заявляется. Установку или автоматический перезапуск probe не инициировал.

Ревью и независимое ревью нашли P2: при закрытии Display исключение из начального publish до try/finally оставляло checking=true. Теперь начальные действия входят в try/finally; ui boundary подавляет только ожидаемое ERROR_DEVICE_DISPOSED, повторно проверяет закрытие перед callback. Прочие UI-ошибки не скрываются. Независимый harness подтвердил освобождение флага и успешный следующий check. Старый fetch/уведомление после stop/start отбрасывается по lifecycle-эпохе. Окончательное независимое ревью новых подтверждённых P1/P2 не обнаружило.

Ни одна база не запускалась. Своя EDT остановлена, исходные bundles.info/1cedt.ini и UI preferences восстановлены побайтно; временный probe отключён, собственная копия p2-профиля удаляется после финальной проверки публикации. Пользовательские EDT/базы не изменялись. Evidence: .runs/release-updates. После merge сверяются class-файлы кандидата; после публикации отдельно проверяются обычные публичные URL/SHA256 и разрешение p2 зависимостей.
