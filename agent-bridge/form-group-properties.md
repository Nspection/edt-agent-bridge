# Свойства групп управляемой формы

`inspect_form_layout(include_properties=true)` возвращает у группы обычные scalar-свойства, `properties.extInfoType` и вложенный `properties.extInfo`. Чтение показывает текущий тип расширения и эффективные значения, включая значения по умолчанию.

Для `UsualGroup` можно передать, например:

```json
{"op":"set_item","item_name":"Card","set":{"extInfo":{"group":"Vertical","showAsCard":true,"representation":"None","showTitle":false,"united":false}}}
```

Поддержаны вложенная карта `extInfo`, ключ вида `extInfo.group` и плоское имя свойства, если оно однозначно принадлежит расширению группы. Тот же `set` применяется при `add_group`. Для Page, Pages, командных и других групп допустимые имена и значения определяет их фактический тип SDK; свойства чужого расширения отклоняются. Расширение не подменяется произвольной ссылкой. Прямое назначение `id` и смена `type` существующей группы запрещены: создайте группу нужного типа штатной операцией и перенесите элементы явно.

Изменения доступны в `mutate_form_model` и в `layout` операции `apply_form_recipe`. Для рецепта существующей формы, который меняет только layout, используется общий адресный механизм мутации и экспорта формы; владелец и Configuration не экспортируются заново. Создание формы, изменение реквизитов или явное изменение свойств владельца имеют свой штатный маршрут.

`edt_validate_request` проверяет свойства существующих элементов на отделённой копии модели, свойства создаваемых групп — на типизированных черновиках. Неподдержанные свойства и значения не получают validation token. Для родителей, которые ещё создаются предыдущими шагами, окончательный native-контекст проверяется внутри атомарной транзакции; это указано в validation checks. Если исходники изменились после валидации, перечитайте модель и получите новый токен.

После применения перечитайте форму и сравните `properties.extInfo` с ожидаемыми значениями. Runtime может оптимизировать группы с `united=false` и не предоставлять их как отдельные элементы коллекции — это поведение платформы, а не доказательство потери группы из исходников. Для визуального результата проверяйте preview и разрешённый тестовый клиент отдельно.
