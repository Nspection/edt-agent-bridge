# Актуальность native-предпросмотра формы

`edt_editor_form_preview(mode=refresh|select, capture=true)` обновляет текущую чистую форму native-рендерером EDT и связывает снимок с завершившейся генерацией. Переключение Module → Form, повторное открытие, сохранение и изменение формы для этого не нужны.

`editor_ready` означает готовность вкладок. `ready=true` у form preview означает совпадение авторитетной BM-модели, модели редактора, ревизии файла и установленной новой native generation. На активной странице формы обычный `edt_editor_snapshot` возвращает `ready=false` и `next_call` к проверяемому native capture вместо ненадёжного оконного PNG. Одна задержка не доказывает актуальность изображения.

`projection_freshness.model_sha256` можно передать как `expected_model_sha256` следующему вызову. Fingerprint охватывает containment модели Form и URI ссылок. Содержимое внешних зависимостей, включая `.dcssca`, не проверяется; `external_dependency_contents_verified=false`. Готовая генерация не доказывает визуальную корректность — снимок следует осмотреть.

Защиты: dirty editor не сохраняется и не сбрасывается; смена editor/input/model, lifecycle epoch или source revision отменяет подтверждение; reader имеет ограниченный pool и общий 30-секундный бюджет с UI-очередью. После таймаута поздний callback не рендерит. Native completion adapter проверяет точные версии SDK presentation `16.0.2.v202607090722` и layout `15.0.1.v202607090722`; неизвестный SDK возвращает unverified. Это явно ограниченный адаптер к внутреннему API, который требует повторной проверки при обновлении EDT.

Приёмка в собственной изолированной EDT: уже открытая чистая форма, внешнее изменение двух заголовков с LF/autoWidthInTable None и headerHeight=2, refresh без переключения вкладок, совпадающие BM/editor hashes и осмотр двухстрочных заголовков. Исходная собственная форма восстановлена байт-в-байт. Пользовательская EDT и базы не использовались.

## Захват native-изображения

С `1.4.0.20261116reports4` capture сохраняет **саму native-форму**, без панелей редактора и заголовка окна. `capture_scope=native_form_body_from_same_renderer_cache`, `capture_id` — отдельная квитанция растрового захвата. Установленный буферный `ImageData` используется напрямую; для проверенной Windows SDK в обычном режиме адаптер временно направляет существующий renderer cache в собственные ограниченные файлы, затем обязательно восстанавливает обычный HWND-вывод. Глобальные флаги/сервисы SDK и поля renderer редактора не подменяются. Это не desktop screenshot, поэтому окно другого приложения не попадает в PNG.

SDK может проглотить исключение callback; отдельный terminal result сохраняет отказ paint/decode/restore/других callbacks. Ошибка восстановления снимает прежнюю квитанцию freshness. Неподдержанный контракт, неизвестный исход восстановления, изменение generation, неполный буфер или превышение лимита не возвращают успешное изображение. Буферы создаются уникально и освобождаются после захвата. `viewport_equivalence_verified=false` и `visual_correctness_verified=false`: готовая модель и native PNG не заменяют визуальную проверку выбранной страницы и прокрутки.

Штатные успешные SDK/BM проходы отрисовки могут повторяться; адаптер допускает до четырёх paint/restore проходов, создавая отдельный layout service для каждой BM-попытки. Любой неизвестный/ошибочный исход блокирует последующие проходы этого захвата. Штатный popup cache текущего renderer может вырасти до четырёх скрытых дочерних controls; проверяются parent/состояние нового элемента, верхние окна и активация не создаются, существующие SDK controls не удаляются.
