# EDT Agent Bridge 1.4.0.20261110zzzzzzzui1

Единый UI-прогон через `edt.run op=ui`: подготовка собственного TestClient, пакет до16 шагов с проверками, короткий итог, снимки своего приложения и проверяемая уборка. Подробный результат сохраняется до удаления клиента и доступен через ui_run_id.

- Долгие формы и карты: operation_timeout_s5..300 на команду/весь пакет, wait_timeout_ms в пределах этого бюджета на условие шага. Для формы на30с:90с на пакет и60с на шаг. Без переопределений стандартные значения:90с старт,25с операция,10с явное postcondition.
- Внутренний receive/stdio согласованы с выбранным бюджетом. Короткий poll больше не обрывает уже начатый ответ; явное postcondition по умолчанию ждёт до10с. Настоящий EOF/неполный ответ на транспортном лимите по-прежнему прекращает канал без пересылки мутации.
- Диагностика времени очереди, проверки Python, запуска процесса, протокола, UI и уборки. Порог slow10с диагностический, не ошибка.
- Ошибка шага останавливает пакет; неизвестный исход не обходится новым ключом. Только собственные runtime-ресурсы убираются автоматически; бизнес-данные/проект/база не удаляются и предыдущие записи не откатываются.
- Review fixes: отсутствующий оригинальный журнал не подтверждает cleanup; сбой учёта сессии не теряет полученный ответ и не выдаёт успешную приёмку.

807 Java-тестов,41 worker- и16 table-контрактов, standalone boundary и p2. В собственной EDT/1С8.5.1.1522 проверены9 шагов сохранения/повторного открытия, заданные90/60с, ошибка в середине пакета, обрыв процесса/worker, повтор ключа и уборка. Контрольный31-секундный socketpair-ответ принят с расширенным бюджетом; это не приёмка отрисовки конкретной карты TMS. Review fixes покрыты контрактами; основной путь runtime неизменён. Все собственные базы/клиенты/проекты убраны. Пользовательская EDT при выпуске не изменялась.
