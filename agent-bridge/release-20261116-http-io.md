# EDT Agent Bridge 1.4.0.20261116reports3

Исправлен воспроизведённый механизм HTTP-зависания из расследования №46: неполные headers/body и нечитающие клиенты больше не удерживают обработчики бессрочно. Каждая активная сетевая фаза ограничена10 секундами; контроль чтения заканчивается до исполнения тяжёлой операции, контроль отправки начинается после неё. Бизнес-операции не прерываются и не повторяются.

Пул разбора HTTP использует16 обработчиков и ограниченную очередь; тяжёлые операции сохраняют отдельный лимит4 и явный отказ server_busy до исполнения. Метрики /health/ready различают таймаут входящего HTTP и отправки готового ответа. Обрыв после исполнения сохраняет неизвестность доставки и не разрешает повтор мутации.

Реальные TCP-тесты воспроизводят отказ исторической версии и восстановление новой без закрытия зависших соединений клиентом. В собственной EDT проверены53 чтения форм на фоне зависших запросов, истечение16 неполных тел и16 заголовков, сохранение сессии. Пройдены1341 Java-тест,139 TestClient Python-тестов и проверки упаковки/OSGi/PowerShell; выполнено собственное и независимое ревью.

Точный сокет/триггер исходного авторского эпизода установить без его журналов нельзя; подтверждены и исправлены конкретные причинные пути сервера. Подробности и границы доказательств: [расследование №46](issue-46-http-starvation.md).

Native DLL и EPF переиспользованы без изменения байтов из reports2. Пользовательская EDT и базы не затрагивались.
