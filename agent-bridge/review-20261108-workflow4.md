# Ревью короткого рабочего цикла — 2026-11-08

Область: `edt_session_summary`, `edt_check`, компактные статусы, курсоры событий и существующий исполнитель сценариев.

## Подтверждённые замечания и исправления

1. После перезапуска EDT статус возвращал всю сохранённую историю, игнорируя after_cursor. Исправлена фильтрация и проверка диапазона курсора. Порции краткого ответа содержат не более 20 событий с отдельными next/latest cursor и признаком потери старой истории.
2. Повтор start с тем же ключом после перезапуска мог создать новый прогон: ключи хранились только в памяти. Для новых прогонов сохранён claim с run ID и хешем аргументов до запуска работника. Повтор возвращает прежний статус, смена аргументов отклоняется. Утрата снимка при существующем claim означает outcome_unknown без повтора. Непоставленные в очередь задания освобождают собственный claim. Старые прогоны до этого изменения не получают гарантию задним числом.
3. Сводка повторно разрешала default-приложение после чтения синхронизации: при смене пользователем приложения могли смешаться имя одной базы и состояние другой. Имя/UUID теперь возвращаются вместе с состоянием для одной native-ссылки.
4. Большие исключения и подписи шагов могли раздувать компактный ответ. Добавлены пределы текста с явными флагами усечения, без разрыва пары UTF-16. Полные ответы сохранены.

## Остальные проверенные свойства

- Короткий start требует явный update_db; не создаёт базы и не расширяет область действий существующего native/Vanessa исполнителя.
- Неизвестная готовность секции не превращается в READY. Настроенный профиль не объявляется живой готовностью Vanessa.
- Полные ответы прежних status-команд сохранены по умолчанию; compact включается явно.
- Краткая выдача не копирует произвольный controller result, переменные, BSL или журналы.
- Краткая команда не подтверждает визуальный checkpoint автоматически и не выполняет откат данных при cancel.
- 461 Java-тест и 24 контракта PowerShell прошли; локальный p2 verify-only прошёл.

Живой прогон Vanessa и окончательная уборка фиксируются в отдельном отчёте проверки. До завершения живой проверки кандидат не публикуется как подтверждённый полный цикл.
