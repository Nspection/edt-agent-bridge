# Короткие инструменты формы и итоговый отчёт

Доступно с выпуска `1.4.0.20261108workflow7`. Установленные команды и схемы проверять через edt_capabilities. Прежние edt_runtime_catalog/observe/action, native BSL, Vanessa и отладчик сохранены.

## Что уже подготовить

Нужен отдельный менеджер Vanessa с client_mcp, VanessaExt и подключённым TestClient. Команды не запускают базу и не устанавливают расширения. Передавать endpoint локального менеджера (по умолчанию http://127.0.0.1:9874/mcp), а не endpoint EDT. Фасад проверяет наличие используемых параметров в схеме установленной Vanessa; несовместимая версия возвращает ошибку, а не пытается нажимать мышью.

## Прочитать текущую форму

```json
{"view":"elements","max_depth":3,"limit":30}
```

Передать в `edt_form_state`. Возвращаются snapshot_id, captured_at, window, исходный инструмент, строки семантического дерева, total/has_more/next_offset. Дерево сохраняет текстовое представление Vanessa, включая её обозначения типов и флагов; это не отдельная DOM-модель и не OCR. Учитывать видимость родительских групп: флаг самого поля ещё не означает доступность пользователю.

- `view=elements`: компактное дерево, max_depth=1..20, only_visible; table/group ограничивают соответствующую часть дерева.
- `view=values`: состояние формы в Gherkin-представлении Vanessa, включая доступные ей значения; не обещает прочитать все данные базы или все строки динамического списка.
- `view=messages`: сообщения пользователю.
- `view=element, element=<имя>`: тип/вид/значение и флаги одного элемента в представлении Vanessa.
- `view=windows`: список окон TestClient.

Данные всех этих вызовов сохраняются как неизменяемый снимок вне Git. Для следующей страницы не опрашивать форму заново:

```json
{"snapshot_id":"form-...","offset":30,"limit":30}
```

Это страница **сохранённого** снимка, а не живое состояние (`live_state=false`). Новое чтение без snapshot_id создаёт новый снимок. Максимум 100 строк на страницу, строки разбиваются на части до 1200 символов; весь снимок ограничен 2 MiB. При слишком большом дереве использовать table/group/max_depth. В values/messages эти ограничения области не применяются — команда явно отклоняет неподходящие параметры.

Снимки не имеют подтверждённой связи с проектом EDT: endpoint выбирает менеджер и его активный TestClient. Перед работой сверить подключённую базу обычным процессом настройки. При смене заголовка активного окна во время захвата снимок отклоняется. Это не атомарная блокировка формы; состояние может измениться после наблюдения.

`get_table_data` у Vanessa читает данные объектов базы, а не просто видимые строки UI. Новые команды не подменяют одно другим. Для специальных операций остаётся edt_runtime_catalog → edt_runtime_observe с точной схемой. Для настоящего изображения использовать edt_runtime_observe(tool=get_window_screenshot_os) и прочитать возвращённый image_path; строка с путём ещё не означает, что агент просмотрел снимок.

## Выполнить одно действие

```json
{"action":"input","element":"Наименование","value":"Тест","expected_window":"<точный window из чтения формы>","idempotency_key":"<задача-ввод-1>"}
```

Передать в `edt_form_action`. Доступны:

| action | Адрес и значение | Действие Vanessa |
|---|---|---|
| input | element, value (строка, в том числе пустая); необязательно table | input_text; пустое значение — clear_field |
| choose_value | element, value (представление из списка); необязательно table | set_value |
| command | element; необязательно table | click_button |
| tab | element страницы | switch_tab |
| row | table, row_criteria вида Код=001;Наименование=Тест | navigate_to_row |
| check/uncheck | element флажка | set_checkbox/unset_checkbox |

Пустой input очищает поле штатным clear_field без параметра value (в том числе при table); choose_value требует непустое представление. input предназначен для текста/простых типов; choose_value выбирает представление из списка, а не назначает произвольный UUID ссылки. Переключение страницы и поля адресуются именами/заголовками, поддержанными Vanessa, без координат или системной клавиатуры. Для неоднозначных заголовков выбирать внутреннее имя из дерева.

Всегда нужны idempotency_key и точный expected_window. Фоновый работник ещё раз читает заголовок **перед отправкой**; при несовпадении действие не отправляется. Проверка заголовка не является уникальным идентификатором окна: одинаковые заголовки и смена состояния после проверки остаются ограничением TestClient API.

Ответ — job_id; опрашивать edt_operation_status. Сохранённый terminal-повтор после перезапуска может вернуть state/result без нового job_id; для этого не нужен работающий endpoint. Успех задания не означает бизнес-успех операции: повторно прочитать элемент/значения/сообщения через edt_form_state, при необходимости снять изображение. postcondition_verified=false напоминает, что автоматической проверки требуемого бизнес-эффекта нет. Если остановил отладчик, использовать отдельные debug-команды.

Повторять запрос только с прежним ключом и неизменными аргументами. После потери ответа/перезапуска неизвестный исход не обходить новым ключом — сначала наблюдать приложение. Дедупликация использует прежний механизм VanessaMcpBridge; в него включён и expected_window. Получение каталога/снимка не запускает действие автоматически.

## Получить итоговый отчёт

```json
{"project":"<проект>","baseline_id":"check-...","run_id":"dev-...","data_run_ids":["data-..."],"form_snapshot_ids":["form-..."]}
```

Передать в `edt_task_report`. Необязательные поля добавлять только при наличии соответствующих идентификаторов; также доступен files как у edt_check. За один вызов собираются:

- текущая компактная сводка edt_check и результат указанного прогона;
- состояние до 10 явно переданных журналов, pending-счётчики и подтверждённые исходы уборки без значений записей;
- до 10 сохранённых наблюдений формы (время/окно/вид), без повторного чтения клиента.

Команда не начинает тест, не вызывает set_status/advance_set, не удаляет данные и не завершает host. Ошибка project/baseline/run — ошибка отчёта; недоступный явно переданный журнал/снимок — unknown_sections, не зелёный результат. Журнал проверяется по текущей привязке базы EDT. Учитываются только явно переданные журналы, не все когда-либо созданные данные.

runtime_verified=false, scenario_sources_match=not_verified: исторический прогон не доказывает, что все текущие файлы тестировались. project_binding_verified=false/visually_reviewed=false у снимков: приложение не считается привязанным к проекту или просмотренным глазами автоматически. database_cleanup_verified=false и data_may_remain из журнала не заменять утверждением о физической уборке. Подробности доступны прежними edt_check(details), edt_development_run_status, edt_test_data и edt_form_state(snapshot_id).

## Проверки и ревью

539 Java-регрессий и границы standalone-пакета прошли. В отдельной EDT 2026.1.2.2 проверены регистрация команд и настоящий HTTP MCP-маршрут с управляемым сервером **Vanessa-протокола**: пагинация, input/tab/command, отсутствие дубля при повторе ключа, отказ при неверном заголовке, наблюдение после действия. Это не запуск настоящего TestClient Vanessa. Итоговый отчёт дополнительно проверен с настоящими проектом и одноразовой файловой базой 1С 8.3.27.2325, созданной через EDT. Живой приёмки UI на настоящей Vanessa/пользовательских формах в этом выпуске не заявлена.

Основное и независимое ревью: исправлены пустой ввод, зависимость списка окон от активной формы, offline-повтор завершённого действия и сериализация проверки/отправки для конкурентных действий через одно соединение. Sensitive-метки UI-команд и статуса, скрытие значения фоновой ошибки и редактирование MCP request/tool/response trace исключают запись значений форм в общие журналы. В разрешённом MCP-ответе данные остаются; локальные снимки/квитанции по назначению могут содержать данные формы.

Локальные доказательства финального кандидата: .runs/release-forms/live.json, live-protocol.log, tests.log, cleanup.json; исходный прогон — .runs/form-tools. Итоги уборки фиксируются отдельно с проверкой точных путей. Живая приёмка UI на настоящем клиенте Vanessa остаётся неподтверждённой: локальный управляемый сервер проверяет протокол, а не поведение платформенных элементов.
