# Сетка и линейки на снимках

Опциональные параметры: `grid=true`, `grid_step=20` (целое число 8..500 px). По умолчанию сетка выключена. Сетка наносится после захвата в отдельный PNG: интерфейс, масштаб изображения и оригинал не меняются. Обработка выполняется вне SWT UI-потока и после освобождения очереди editor-запросов. Общая очередь аннотаций ограничивает суммарную память растров: одна операция за раз, ожидание до 30 секунд.

## EDT

`edt_editor_snapshot(editor_id, grid=true, grid_step=20)`; через компактный вход используйте контракт `edt.help` для этой операции. Параметры также доступны в каждом элементе `edt_editor_capture_batch.items` и у `edt_editor_form_preview`, `edt_editor_scroll`, `edt_editor_view` с `capture=true`. Неверные параметры отклоняются до действий с редакторами; batch проверяет все элементы до первого открытия.

## Native

После выполнения существующего пакета со `screenshot=true` либо вызовами `КомпонентаАгента.Screenshot()`:

```json
{"action":"snapshots","host_id":"<owned-host>","request_id":"<original-request>","grid":true,"grid_step":20}
```

Это аргументы `edt_runtime_host`, доступного через компактный контракт. Сначала проверяются исходные манифесты и SHA256. Получение копий не вызывает Screenshot/BSL повторно и не меняет результат пакета. Параметры grid/grid_step относятся только к action=snapshots; новый ZIP Native не требуется.

## Результат и координаты

- `image_path`, `width`, `height` и существующий `sha256` сохраняют исходный смысл: оригинал без аннотаций.
- `original_image_path`, `original_sha256` явно указывают исходник.
- `alignment.image_path`, `alignment.sha256`, `alignment.width/height` — копия с сеткой и линейками.
- Координаты подписаны в пикселях оригинала, от (0,0), без пересчёта в логические координаты интерфейса/DPI. В копии начало оригинала смещено на `alignment.origin_x=32`, `origin_y=32`: рамка с линейками добавлена сверху и слева. Для точки (x,y) оригинала используйте (x+32,y+32) на копии. Для сравнений отступов смещение сокращается.
- Линии идут через grid_step, подписи реже, чтобы не перекрывались. Это вспомогательный инструмент визуальной проверки; наличие PNG не доказывает правильность формы.

Производные файлы лежат в подпапке `alignment` рядом со снимками. Повтор одинаковых параметров возвращает ту же копию. Изменённую копию механизм сохраняет и сообщает ошибку; оригинал не перезаписывается. При отказе аннотации исходный результат остаётся доступен вместе с `alignment_error` и `alignment_applied=false`. В batch это `captured=true`, но `all_succeeded=false`; Native дополнительно возвращает `alignment_all_succeeded=false`. Не повторяйте действия интерфейса/BSL ради аннотации. PNG публикуется через временный файл и rename без перезаписи существующего результата. Размеры изображения и хранилище ограничены (128 производных файлов / 256 MiB на каталог); счётчик оригинальных Native-снимков остаётся отдельным. Уборка собственного host удаляет его каталог вместе с копиями. Для EDT удалять только снимки своей задачи, сохраняя ранее существовавшие.

Проверки: regression-тесты сохранности байтов/координат/границ/контрактов/квот; снимок редактора формы в отдельной EDT; настоящий Windows Native-захват собственного тестового окна → authenticated channel → получение копии. Тест окна Native не является проверкой поведения прикладной формы 1С; алгоритм захвата и Native ZIP в этой доработке не менялись.
