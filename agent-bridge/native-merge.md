# Native сравнение и объединение через MCP

Bridge использует IComparisonManager/IComparisonSession EDT, дерево сравнения и TextNodeCustomMergeSettings. Изменения проектов выполняются штатным startMerge; текстовые замены XML или git merge не используются как реализация объединения.

## Четыре рабочих сценария

1. **Подготовить план.** Создать сравнение, прочитать различия, выбрать конкретные узлы/правила и при необходимости подготовить ручной результат BSL. Вызвать `edt_compare` с `action=handoff`: откроется штатное окно той же сессии. Остановиться, не вызывать apply. Пользователь может править настройки и сам нажать «Объединить».
2. **Продолжить после пользователя.** Найти сессию через `sessions`/`status`, перечитать текущий план и результаты узлов. Использовать новые хеши после пользовательских правок. Не воспроизводить старые флажки и не перезаписывать текст первоначальным решением агента.
3. **Выполнить полностью.** В пределах разрешённой задачи подготовить план, применить свежий plan_sha256, проверить native status, исходники и диагностику. Если задача требует поведения в базе — затем Vanessa/отладчик. Успешная native-команда не доказывает правильность бизнес-логики.
4. **Передать сомнение.** Вызвать `handoff` с node_id и reason. EDT выделяет найденный узел, добавляет колонку «Вопрос ИИ» со значком предупреждения у спорного узла. При наведении на значок показывается текст вопроса; пояснение также видно в статусной строке. Несколько вызовов сохраняют вопросы у нескольких узлов; пустой reason удаляет вопрос выбранного узла. Проверить highlighted=true и review_column_installed=true; если дерево ещё загружается, повторить открытие/подсветку. Слияние не запускается.

## Команды

| MCP | Назначение |
|---|---|
| edt_compare | start, sessions, status, tree, details, open_ui/handoff, close |
| edt_merge_plan | Прочитать план; с rule/node_id/expected_node_sha256 изменить правило одного узла |
| edt_merge_result | read/write/patch текста BSL-модуля или метода в native custom settings |
| edt_merge_apply | Применить план по свежему expected_plan_sha256 |

**MAIN — основной/левый проект и получатель изменений. OTHER — второй/правый источник.** ancestor_project включает трёхстороннее сравнение. `matching`: UUID, NAME, UUID_THEN_NAME. По умолчанию сравнивается структура методов, удаления основного проекта запрещены.

Новые MCP-сессии начинают с пустого выбора изменений. Существующие native-сессии обнаруживаются без сброса их настроек. `keep_main` исключает узел из объединения, `take_other` выбирает правую сторону. `prefer_main`/`prefer_other` доступны только там, где их разрешает EDT. Доступные правила возвращаются в узле.

Пример начала:

```json
{"action":"start","main_project":"Target","other_project":"Source","ancestor_project":"Base","parse_bsl_structure":true,"scope":["Document.Example"]}
```

Дождаться COMPARISON_PROCESS_FINISHED через status. `tree` возвращает строковые node_id, пагинацию и флаги различий; `details` — значения сторон и node_sha256. При структурном сравнении BSL возвращается текст выбранного метода по регионам EDT, а не весь содержащий модуль.

Для ручного результата передать action=write, content и свежий expected_node_sha256. `patch` требует единственного совпадения old_text; new_text может быть пустым. Изменяется native буфер CUSTOM_MERGE, исходники остаются прежними. Синтаксические ошибки возвращаются отдельно; при применении некорректный custom BSL блокируется. EDT может не разрешать custom result для всего модуля в структурном режиме: тогда редактировать конкретные методы или использовать отдельную сессию без разбора структуры.

## Защита состояния и границы

- Узлы и план защищены хешами. В снимок входят native merge settings, порядок подчинённых, пользовательские флаги и custom settings, в том числе у исключённых узлов. После ручных изменений нужны новые хеши.
- Перед применением проверяются исходные файлы всех сторон. Если они изменились после начала/подключения, требуется новое сравнение; MCP не переносит автоматически старый план на другие исходники.
- Несохранённые редакторы и открытые модальные диалоги блокируют запись/применение. Текст, ещё не подтверждённый в native диалоге редактирования, не выдаётся за сохранённый результат: live_editor_buffer=false. Пользователь должен подтвердить/сохранить его штатным способом, затем агент перечитывает результат.
- Колонка вопросов добавляется в текущий native-редактор, не записывает пометки в проекты и не подменяет штатные флажки/правила объединения. В режиме подготовки плана окно остаётся для пользователя; применение/закрытие сессии завершает этот просмотр.
- startMerge асинхронный: accepted=true означает только принятие команды. Опросить status до applied=true/MERGE_PROCESS_FINISHED либо ошибки. Bridge запоминает событие успешного завершения, поскольку EDT сразу освобождает native-сессию; native_session_present=false после успеха нормально.
- Handoff не нажимает «Объединить» и не планирует автоматический apply. Пользовательская кнопка выполняет штатное объединение EDT.
- Идентификатор MCP привязан к конкретному экземпляру native-сессии, а не только к паре проектов/scope. Исторический session_id не может редактировать новый запуск; close такого идентификатора удаляет только старую запись. session_replaced=true сообщает о новом сравнении с той же областью.
- Handoff ищет уже открытый native-редактор соответствующей сессии. Повторный вызов сохраняет editor_input_uuid; editor_reused показывает переиспользование. Пока дерево ещё загружается, повторный запрос сохраняет уже созданную вкладку.
- Чужие UI-сессии не закрываются командой close. Собственную сессию можно закрыть без применения.
- Текущая реализация рассчитана на локальные открытые EDT-проекты workspace. Источники из файловой системы/Git-ревизий напрямую не подключаются. Сессии действуют в текущем запуске EDT; долговременный экспорт/восстановление плана отдельно не реализован.
- Обход дерева ограничен 100000 узлами, текст узла — 1 МБ. Для больших конфигураций использовать scope по объектам; это не измеренный тест производительности на полной TMS.
- Приоритетные правила могут не иметь готового текстового preview до native объединения; result_source=not_materialized нельзя интерпретировать как пустой корректный результат.
- Проверка BSL перед применением синтаксическая. Полная диагностика выполняется после объединения. Ошибка native merge не означает обещание автоматического отката; результат и исходники нужно проверить.

Для контроля раскладки `edt_window(action=state)` теперь возвращает open_perspectives и active_perspective. Команды сравнения не сбрасывают перспективы.

## Подтверждённая локальная проверка

В EDT 2026.1 установлена сборка `1.4.0.20261106review3`. Регрессионный набор: **223 теста**. Через реальный MCP выполнено **24 проверки** на трёх отдельных EDT-проектах: трёхстороннее сравнение BSL по методам, перенос `descriptionLength` 25→40, ручной результат со связью методов обеих сторон, передача той же сессии в native-окно, выделение узла и колонка вопроса, чтение изменённого native custom result, блокировки устаревшего плана/ошибочного BSL/изменившегося источника, штатное применение, сохранение UUID, неизменность OTHER/предка, повторное сравнение и 0 ошибок диагностики объединённого модуля. Дополнительно проверены повторный handoff без создания новой вкладки, изоляция исторического статуса, запрет правки новой сессии старым id и сохранение нового сравнения после close старого id. Значения порядка и пользовательских флагов проверены отдельными регрессионными тестами на изменение fingerprint. Получен и просмотрен снимок окна: дерево, значок и русская статусная строка отображаются корректно.

Правка после handoff в тесте внесена MCP-командой в те же native custom settings. Физический ручной ввод в диалог EDT, наведение мыши на tooltip и пользовательское нажатие «Объединить» автоматически не воспроизводились. Подсказка реализована стандартным JFace ColumnLabelProvider; кнопка остаётся штатной EDT. Сценарий в информационной базе для этой проверки объединения не запускался.

Все временные проекты проверки удалены через Eclipse workspace API; рабочие TMS/WMS/АФВ не объединялись и не удалялись. После перезапусков сохранены открытые перспективы 1C, Debug и Git. Причина первоначального исчезновения пользовательских перспектив не установлена; в проверенном цикле проблема не воспроизвелась, сброс перспектив в Bridge не найден.

Воспроизводимый прогон (требует работающей EDT с Bridge):

```powershell
python tools/audit-edt-merge.py --output .runs/creation-audit/merge-new-run --apply
```

Каталог должен быть новым. Скрипт создаёт собственные проекты с уникальными именами, сохраняет локальный `report.json` со снимком и удаляет свои помеченные проекты в finally. Авторизация читается из локальных MCP-настроек и не записывается в отчёт. Публикация update site/коммит этим локальным прогоном не выполняется.
