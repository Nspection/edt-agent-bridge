# Ревью и приёмка диагностик v8std

Кандидат 1.4.0.20261112zzzv8std1. Собственное и независимое ревью завершены, открытых подтверждённых P1/P2 нет.

Независимый reviewer воспроизвёл два P2 отдельным Java harness: серверный lowercase неизвестного кода приводил к unavailable; параллельный запрос другого кода мог дождаться чужого batch и остаться без продолжения. Исправлены нормализация/сопоставление ID и планирование своего набора после чужого ожидания; добавлены регрессионные проверки. Отдельно описание статьи помечено description_scope=article_intro и не выдаётся за правило выбранного anchor.

1002 Java regression-теста и standalone boundary прошли. Независимый повторный harness подтвердил unknown, два разных concurrent batch, уникальный contributor, offline, ограничение 100 advisory items из 10000 rows и отсутствие исходных сообщений в справочном ответе. Worker/Native/BSL не изменялись; запуск 1С для этих изменений не требовался.

Собственная headless OSGi/EDT-конфигурация и отдельный workspace: создан синтетический Eclipse problem marker с checkId; baseline → changes не дал ложного delta; details сохранил ID и получил std703. Настоящий Java HttpClient обратился к публичному v8std за диагностическими ID, получил std703/std499 и unknown_code. Проверены отдельный блок get_diagnostics, сохранение прежнего сообщения, include_standards=false и чтение дискового кеша при отключённой сети. Тестовый проект удалён. Это не приёмка анализа реальной конфигурации или всех checkers EDT: registry contributors в headless окружении был пуст, правило уникального contributor проверено unit/harness. Базы 1С, пользовательская EDT и debug-порт 1552 не использовались.

Первый временный probe не импортировал org.eclipse.core.runtime и завершился с NoClassDefFoundError IPath после успешного HTTP lookup; fixture удалился в finally. Исправлен только временный manifest probe, финальный запуск прошёл. В продукт этот тестовый bundle не включён.

Сборка/p2-план проверяются в отдельной конфигурации и копии собственного профиля. После merge классы сравниваются с кандидатом; опубликованный сайт проверяется по обычным URL, SHA256 и p2 verifyOnly. Доказательства: .runs/release-v8std/.

Локальный p2 verifyOnly прошёл на отдельной копии профиля bridge-v8std-verify с destination собственной Dev EDT. Первые попытки тестового verifier не имели согласованной копии профиля и отказали на отсутствующем старом IU; исправлены только параметры/копия тестового профиля. Установка не выполнялась. Собственные live-workspace/configuration/probe удалены, доказательства сохранены.
