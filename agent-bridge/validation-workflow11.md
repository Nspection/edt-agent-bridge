# Проверка workflow11 — 09.11.2026

Материалы выпуска `1.4.0.20261109zworkflow11`, ветка `codex/agent-efficiency-workflow11`. Первичная живая проверка выполнена на кандидате `1.4.0.20261109zworkflow11f` только в собственной EDT Agent Bridge Dev. Пользовательская EDT и x5 не менялись.

## Реализовано

- `edt_capabilities`: несколько точных имён за вызов, opt-in workflows/схемы/описания, стабильный хеш каталога и условная проверка. Недоступные model-facing команды отфильтрованы.
- `edt_ready`: сервисы, наличие команд, модель и явные требования к базе/профилю без запуска или обновления.
- `edt_operation_status`: ожидание терминального события, краткие итоговые ID и структурированная ошибка. Таймаут не отменяет/не повторяет работу.
- Общий opt-in `response` в поддерживаемом семействе команд: summary/details, выбор полей и ограничение байт, `edt_result` для immutable деталей. NULL, числа и флаги evidence сохранены. Плохие параметры отвергаются до исполнения; усечение не превращает выполненную операцию в ошибку.
- `edt_task_batch`: durable последовательность 1..16 проверяемых шагов, остановка при неуспехе/неизвестном исходе, отсутствие повторной отправки. Формы, edt_check и assertions; host/test-data остаются отдельными командами.
- `edt_task_session(resume)`: binding, страницы истории, ссылки и оставшиеся ресурсы без автоматического повторения.
- `edt_agent_metrics`: счётчики вызовов/байт/времени/ошибок, без сохранения payload и без выдуманной оценки токенов.

## Проверки

652 Java-теста и standalone product boundary прошли. Дополнительно прошли 29 PowerShell-контрактов managed Vanessa. Новые тесты охватывают NULL, Unicode и пагинацию деталей, ограничения размера и числовое переполнение, ошибки до отправки, readiness, notification wait, повторы пакета после восстановления сервиса, неизвестный исход, отрицательный postcondition и client-binding guard.

Живая среда: EDT 2026.1.2.2, Java 17, файловая 1С 8.3.27.2325, Windows x64. Новый проект и одноразовая база созданы native EDT. Новый wait использован для реальных операций. Ready подтвердил сервисы/модель/команды и отверг отсутствующую команду. Bound batch из baseline и receipt завершился; повтор вернул прежние квитанции. После настоящего перезапуска на финальном кандидате resume подтвердил прежнюю привязку/два шага; пакет не переисполнен. Старый ephemeral details ID стал недоступен. Проекция task_report и метрики проверены через MCP.

Большой capabilities-ответ восстановлен через все страницы edt_result и содержимое совпало с исходным ответом после разбора JSON. Короткая проекция не выдаёт пропущенные данные за полный результат.

## Контрольные измерения

Одинаковые текущие схемы трёх команд: три отдельных вызова с повторными маршрутами — 10 688 байта; один пакет имён без описаний/маршрутов — 2 847 байт (на 73,4% меньше, 3→1 вызов). Условная проверка хеша — 108 байт. Это сравнение форм выдачи на текущих схемах, а не измерение старого публичного релиза или фактических токенов модели.

Capabilities со схемами 100 команд: полный JSON — 110 092 байт, summary — 348 байт. Пропущенные детали получаются отдельно, поэтому это не сокращение объёма при последующем чтении всех деталей.

## Границы

Пакет UI-действий/negative expectations проверен контрактными backend-тестами, но не новой живой последовательностью кликов Vanessa в этой работе. Живой пакет состоял из native чтений baseline/receipt. Работа с реальным UI остаётся на уже существующем executor/client-binding; отдельной сертификации всех форм и серверной 1С нет. Readiness не подавляет модальные окна и не исправляет синхронизацию базы. Исторические инструменты целиком на новый формат ошибок не переведены. Детали кешируются только в памяти и могут истечь/быть вытеснены; resume не восстанавливает код/пароли или ручной merge-план.

## Уборка

Task cleanup подтверждён, сессия закрыта. Одноразовая база, её ассоциация/регистрация и проект удалены native командами; fixture root отсутствует. Собственная EDT закрыта, bundles.info восстановлен byte-for-byte. Настройки доверия не менялись; новых доверий и launch/probe механизмов этот workflow не создавал. Сохранены только build/test артефакты и локальные доказательства под игнорируемым `.runs/workflow11`. Итоги публикации проверяются отдельно при выпуске; эта запись фиксирует исходные runtime-доказательства и уборку.

## Ревью перед выпуском

Основное и отдельное независимое read-only ревью обнаружили и исправили: потерю вложенных отрицательных исходов при проекции; выдачу глубокого payload на пределе рекурсии; потерю evidence-массивов и длинные вложенные ошибки; недостоверную готовность database=connected по SDK контейнеру; зависимость выбранного проекта от постороннего загружающегося проекта; округление больших числовых границ схем в каталоге. Для всех случаев добавлены регрессии. Независимый рецензент повторно прочитал исправления, блокирующих замечаний не осталось. Рецензент самостоятельно EDT/1С не запускал. Подробности — review-20261109-workflow11.md.

## Финальная сборка выпуска

На `1.4.0.20261109zworkflow11` повторно прошли 652 Java-теста, standalone boundary и 29 controller contracts. Финальные JAR загружены в частную EDT: повторены discovery, native project/create/provision с новым operation wait, batch baseline/receipt, response/details roundtrip и метрики. database=connected на реально привязанной базе осталось blocked с connected_verified=false; SDK container не принят за доказательство. После настоящего перезапуска финальных JAR resume сохранил привязку/два шага, batch не переисполнен, старые ephemeral details недоступны. Затем сессия закрыта, база/проект/регистрации удалены, private EDT закрыта и bundles.info восстановлен. Локальный p2 update plan прошёл verify-only в отдельном клонированном профиле без изменения пользовательской установки.
