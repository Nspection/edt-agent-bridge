# Компактный MCP и привязка зарегистрированной базы

Проверено 10 ноября 2026 в отдельной EDT Agent Bridge Dev, MCP 8769,
платформа 8.5.1.1522. Пользовательская EDT и базы не изменялись.
Ветка `codex/compact-surface-and-binding`; кандидат
`1.4.0.20261110compactbindfinal3`. Это данные приёмки кандидата до релизного коммита.
Релиз: [1.4.0.20261110zzzzcompact1](release-20261110-compact.md).

## Реализовано

- До десяти компактных входов. Контракты операций раскрываются по запросу;
  полные старые схемы доступны через `tools/list {profile:legacy}`.
  Все исходные имена вызываются напрямую. Мутации проходят прежний dispatcher,
  authorization и validation token; deny/ASK не обходятся.
- `edt.run op=route`: план Native для кода/запросов/данных, TestClient для
  поддерживаемого UI с Python, Vanessa для сценариев/неподдерживаемого UI.
  План не запускает базу и не устанавливает зависимости автоматически.
  Неизвестный исход блокирует повтор/переключение исполнителя.
- `edt_infobase_bind`: список зарегистрированных UUID, preview и защищённый
  apply для контекста текущей ветки. Не принимает произвольный путь, не
  меняет сохранённые пароли/платформу, не обновляет и не запускает базу.
  Чужие владельцы, устаревший preview и неявная замена основной базы отклоняются.
  Durable receipt предотвращает повтор неизвестной/частичной мутации.

## Доказательства

- Кандидат final3: 743 Java-теста и проверка standalone product boundary прошли.
  На final2 два полных прогона имели разные сбои очистки временных каталогов
  Windows; финальный прогон после закрытия EDT прошёл полностью.
- Живой каталог: 156 прежних операций полностью покрыты компактным discovery.
  199750 байт полных схем против 5456 байт десяти входов — уменьшение на 97.3%.
  Это объём schemas JSON, а не измерение токенов всей задачи.
- Через компактные вызовы штатно созданы собственные проект, справочник, форма
  и две disposable файловые базы вне workspace/home. Обе достигли native EQUAL.
- Привязка: отказ без replace_primary; успешное переключение зарегистрированной
  base-a после base-b; свежая session summary подтвердила нужный UUID. Повтор
  receipt вернул тот же результат. Прежний connect_infobase всё ещё отказал
  этому внешнему пути с INVALID_PATH.
- Живая проверка binding охватывает выбор уже ассоциированной регистрации
  основной для проекта. Первичную ассоциацию, изменение context/target,
  чужого владельца, частичный исход и restart/replay проверяют fake-gateway
  контракты; отдельная живая первичная ассоциация после отвязки не проводилась.
- Route: query -> Native; поддерживаемый UI -> TestClient; choose_value ->
  Vanessa; outcome_unknown -> blocked. Probe не устанавливал Python.
- Затем плагин сам подготовил собственную управляемую Python-среду. TestClient
  запущен без python_path. Batch из 9 шагов открыл форму, создал запись,
  заполнил наименование, сохранил, открыл повторно, проверил значение и закрыл.
  Все postconditions подтверждены; повтор идемпотентен. Summary 2461 байт,
  полный результат 5669 байт. PNG просмотрен: Compact acceptance в списке.
- p2 update site и ZIP собраны официальным FeaturesAndBundlesPublisher.
  Установка пользователю и новая публикация Pages не выполнялись.

## Уборка и порты

Клиент, созданная Python-среда, обе disposable базы, их native регистрации и
настройки приложения удалены с cleanup_verified. Audit-проект удалён native API,
корень собственных fixtures удалён после проверки marker и результатов cleanup.
Тестовая EDT закрыта, bundles.info восстановлен побайтно из исходной копии.
Оставлены только исходники кандидата, локальный пакет и отчёты проверки.

После замечания пользователя тестовая EDT была остановлена; дальнейшая проверка
прошла без debugger launch (session summary: targets=0, launches=0).
Прямой TestClient использовал свой TPort. Пользовательский dbgs.exe на 1552
остался тем же PID 34576 до/после тестов; чужие dbda/ragent не останавливались.
По завершении собственный MCP 8769 не слушает, собственные EDT/TestClient закрыты.

Подробный протокол: [compact-tools.md](compact-tools.md).
Локальные журналы: `.runs/compact-surface/`; снимок: `acceptance.png`.

## Релизная сборка

`1.4.0.20261110zzzzcompact1`: повторно прошли 743 Java-теста, standalone boundary,
30 worker- и 16 table-контрактов Python. Все файлы внутри core/ui JAR совпадают
с живым кандидатом final3, кроме META-INF/MANIFEST.MF с номером версии.
Локальный p2 verifyOnly прошёл в отдельной копии профиля; пользовательские
профили и установка не изменялись. Основное и независимое ревью: подтверждённых
P1/P2 нет, дополнительных исправлений не потребовалось.
