# Табличные макеты в native-сравнении EDT

Доступно начиная с версии `1.4.0.20261107spreadsheet1`. Поддерживаются табличные макеты `SpreadsheetDocument`, присутствующие с обеих сторон сравнения локальных проектов. Проверяемая SDK: EDT 2026.1.2 (compare 28).

## Пользовательский маршрут

1. Открыть штатное сравнение/объединение EDT обычным способом либо через `edt_compare`.
2. В строке табличного ресурса нажать нашу шестерёнку в колонке «Табл.». Типовая команда остаётся доступной.
3. Порядок native-вкладок: «Текущая конфигурация» → «Результат объединения» → «Конфигурация-источник». При трёхстороннем сравнении последней добавляется вкладка «Общий предок». При открытии выбрана вкладка результата.
4. Исходные варианты открыты только для чтения. Результат использует native Moxel control и операции EDT в отдельном локальном BM-контексте. Контекст никогда не сохраняется в модель исходного проекта; сохранение записывает сериализованный результат в native-план. Если native-правило ещё не материализовало результат, начальная рабочая копия берётся из нашего варианта; само открытие ничего не сохраняет и не выбирает для применения.
5. «Сохранить в план» / сохранение редактора записывает результат в `CUSTOM_MERGE` той же сессии. Исходные файлы проекта ещё не меняются.
6. Объединить штатной командой EDT либо поручить применение агенту. При несохранённом результате или изменившихся сторонах применение блокируется. После применения проверить диагностику и повторное сравнение.

## MCP

Обычные пользовательские сравнения обнаруживаются `edt_compare(action="sessions")`. Подключение не сбрасывает существующий выбор; чужая сессия не закрывается командой MCP.

- `edt_merge_result(action="read", session_id, node_id)` возвращает исходные XML-снимки, ограниченную проекцию ячеек, сохранённый результат, `node_sha256`, `draft_dirty`.
- `action="open_ui"` открывает тот же визуальный редактор для табличного узла. `close_ui` закрывает только сохранённую нашу вкладку, сохраняя native-план; грязный черновик не закрывается.
- `action="patch_cells"` принимает свежий `expected_node_sha256`, необязательный `base_side` (`MAIN`, `OTHER`, `COMMON_ANCESTOR`) и `sheet_patch` по контракту `edt_spreadsheet`. Координаты — с единицы. Изменения выполняет штатная модель EDT; операция сохраняет только план, не проект.
- Для нематериализованного результата нужно явно выбрать `base_side`. Сохранённые ручные изменения видны агенту; несохранённые буферы не выдаются за сохранённый результат.
- Если агент изменил план при открытой чистой вкладке, перед передачей пользователю вызвать `open_ui` повторно: устаревшая чистая вкладка пересоздаётся, несохранённые изменения не перезаписываются.
- После сохранения заново прочитать `edt_merge_plan` и передать актуальный `expected_plan_sha256` в `edt_merge_apply`.

Созданные MCP окна сравнения временные и не восстанавливаются после перезапуска EDT с устаревшими идентификаторами сессий. Уже открытые пользователем штатные окна не подменяются; перспективы не сбрасываются.

## Границы и совместимость

В данной SDK ручной результат табличного макета требует адаптации native-участника сравнения. Адаптер проверяет major SDK и структуру менеджера, сохраняет индексы участников и делегирует остальные операции. Это зависимая от версии интеграция с внутренним списком участников; при несовместимой SDK табличная функция отказывает, обычный BSL compare остаётся доступным. Фактическую запись выполняет native `MergeUtils.addPostponedMergeOperation`, включая штатные пути ресурсов и переименования.

XML ограничен 2 MiB, DTD и внешние сущности запрещены, загрузка и сериализация выполняются `MoxelResourceMxlx`. Другие типы макетов, бинарные MXL и односторонние добавления/удаления этим редактором не охвачены.

Рабочие копии редактора находятся в частных локальных BM-контекстах и уничтожаются при закрытии редактора. BM-контекст проекта не сохраняется; его промежуточные данные обслуживает сама EDT в `.metadata`. В исходниках и Git проекта рабочие копии не создаются. Объединение не заменяет runtime-приёмку.

## Семантическое объединение и подсветка

Действия `edt_merge_result` из выпуска 1.4.0.20261108spreadsheet2 дополняют визуальный редактор; проверять наличие по установленной схеме. Данные обрабатываются native-моделью, а не текстовым слиянием XML. Номера пулов форматов/шрифтов/цветов раскрываются в значения; переиндексация одинакового оформления не считается изменением. Незаданные свойства сохраняют native-семантику, общие полосы колонок сохраняют ссылки.

- `semantic_diff` — читающее действие: `offset`, `limit` (1..500), `total`, `has_more`, `unresolved_conflicts`, свежий `node_sha256` и `differences`. У различия есть `id`, `path`, 1-based `row`/`col` (0 для уровня строки/документа), `origin`, `conflict`, `resolved`, `resolution` и краткие значения ancestor/main/other/result. Это ограниченные пояснения, не полный экспорт свойств.
- `auto_merge` — подготовить CUSTOM_MERGE в плане с `expected_node_sha256`. При наличии предка изменение только одной стороны переносится; одинаковое изменение принимается; различающиеся изменения одного свойства становятся конфликтом. Без предка различия не разрешаются автоматически. Независимые свойства могут совмещаться; разные новые объекты в одной координате не смешиваются.
- `resolve_conflicts` — тот же свежий хеш и объект `resolutions`: ключ — актуальный `difference.id`, значение — MAIN/OTHER/COMMON_ANCESTOR/RESULT. RESULT подтверждает сохранённый текущий вариант; предок доступен только в трёхсторонней сессии. Решения относятся к этой сессии. Повторный `auto_merge` сохраняет уже изменённый результат и не воспроизводит старый выбор поверх последующих ручных правок.
- `reveal_difference` с `difference_id` — открыть редактор и перейти к отличию. `set_highlighting` с `enabled` — переключить визуальный слой. `ui_state` — состояние панели/черновика. `save_ui` — сохранить native-черновик в план с проверкой хеша; исходники ещё не применяются.

В редакторе есть цветные отметки и список «Общий предок / Текущая конфигурация / Источник / Результат», переходы назад/вперёд, автоматическая подготовка независимых изменений и кнопки принятия текущего, источника или ручного результата. Подсветка: синий — MAIN, зелёный — OTHER, оранжевый — нерешённый конфликт, жёлтый — ручная правка. Она рисуется поверх документа и не сериализуется как его оформление. Снимок MCP включает панель различий. Таблица показывает до 500 строк за раз; навигация и reveal переключают нужную страницу.

Нативное применение проверяет незавершённые семантические конфликты. Простое сохранение значения MAIN не считается явным решением конфликта: подтвердить выбор кнопкой или `resolve_conflicts`. Несохранённый ввод блокирует запись; сначала сохранить его через EDT или `save_ui`, затем заново прочитать план/хеши. Просмотр и пересчёт подсветки не должны менять dirty-состояние.

Структурные границы: сдвиги строк/колонок определяются по однозначным содержательным опорам; неоднозначное изменение координат становится отдельным конфликтом структуры. Автоматической эвристической перестановки диапазонов, формул и рисунков нет. Пользователь может выбрать структуру стороны целиком или подтвердить вручную подготовленный RESULT. Именованные области учитываются по ключам; одновременные разные изменения списков объединённых областей, рисунков и других сложных коллекций разрешаются целиком, без небезопасного смешивания. После решения проверить фактический макет, диапазоны, параметры и печать; автослияние не доказывает прикладную корректность.

## Сброс ручного результата

«Сбросить результат» в табличном редакторе после подтверждения удаляет сохранённые и несохранённые правки только этого макета и его решения конфликтов. В плане остаётся копия MAIN, исходники проекта не меняются. Независимые изменения можно подготовить повторно отдельной командой auto_merge. Другие узлы сравнения сохраняются.

MCP: `edt_merge_result(action="reset_result", session_id, node_id, expected_node_sha256)` с актуальным хешем. Несохранённый визуальный ввод блокирует MCP-сброс: сохранить через save_ui либо явно сбросить кнопкой редактора. Чистый открытый редактор обновляется автоматически.

Отмена сравнения и запуск новой native-сессии создают новый черновик без прежних решений. Открытие той же сессии сохраняет правки. Если объединение уже применено к проекту, новое сравнение использует изменённые исходники; сброс плана не является откатом проекта.

Внутри вкладки редактора расположены две панели. Шапка «Табличное объединение» содержит действия всего документа: сохранение, заметную кнопку «Сохранить и вернуться к сравнению», автоматическое объединение, сброс и закрытие. Над таблицей различий — только подсветка, навигация, выбор MAIN/OTHER и подтверждение выбранного отличия. Значки Eclipse/Compare имеют подсказки; имена действий сохраняются для доступности. Панели не добавляются в глобальный toolbar EDT.

«Закрыть табличный редактор» закрывает только визуальную вкладку, сохраняя native-сравнение и план. Чистый результат требует подтверждения; для несохранённого предлагаются «Сохранить и закрыть», «Закрыть без сохранения», «Отмена». Вернуться можно через шестерёнку в колонке «Табл.». Выбор стороны/подтверждение доступны только при выделенном различии; пересчёт сохраняет выбор по difference.id.

«Сохранить и вернуться к сравнению» сохраняет текущий результат в план, затем закрывает табличный документ и активирует ту же native-сессию сравнения. При ошибке сохранения редактор остаётся открыт. Эта команда не применяет объединение к исходникам. Обычное «Закрыть табличный редактор» сохраняет отдельное подтверждение и выбор действий с грязным черновиком.

Пересчёт подсветки читает приватную BM-модель через executeReadonlyTask. Если XML и семантические решения не изменились, список различий и макет не перерисовываются. Навигация/прокрутка сами по себе не считаются изменением документа. ui_state не открывает и не активирует вкладку: при закрытом редакторе возвращает opened=false.

Неоднозначная вставка в повторяющийся блок строк/колонок требует решения по структуре даже при наличии неизменившегося уникального заголовка. Это же относится к ручному перемещению строк/колонок в результате: автослияние не накладывает изменения по прежним координатам поверх такой структуры.
