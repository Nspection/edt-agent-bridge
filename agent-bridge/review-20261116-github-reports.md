# GitHub reporting review — 2026-11-16

Scope: the current GitHub reporting UX and MCP flow. Astra medium independently reviewed the implementation and follow-up changes. The main agent reviewed the final diff and performed live testing in an owned isolated EDT with no infobase. No open confirmed P1/P2 remain in this scope.

Architecture: core defines a small asynchronous UI interface, provided by the SWT bundle through OSGi. Durable requests use bounded lifecycle-owned workers and an independent receipt completion mailbox. Human input never holds a shared worker. Stable keys bind payload digests; terminal receipts archive without losing deduplication. Recovery is one-way across process epochs, with deterministic regression coverage. Unknown sends are never replayed.

Review fixes: policy updates compare account ID plus revision; unchanged preference pages never reset policy. UI stop/shell close after Send preserves the actual receipt. Preclaim failure atomically revokes approval only while prepared and otherwise returns the current receipt. Lifecycle dispatch refusal becomes terminal. Large escaped descriptions round-trip within matching storage caps. Outbox locks have bounded waits and no network calls under them. Login uses isolated GCM namespaces and private stdin, checks /user before account binding, clears token widget/char array, and never accepts credentials through MCP.

Live acceptance: MCP auth_start -> protected SWT token/save -> /user; prepare_async arbitrary prose -> exact UI preview -> cancel (prepared, no issue) -> new review key -> SWT Send -> issue42 exact title/body -> close test issue. Duplicate review keys returned the same request; submitted report returned the original issue without a second post. Preferences rendered read-only account and explicit browser/token/verify/review buttons; token dialog cancellation worked. The isolated desktop shell print produced a blank PNG, so no visual screenshot acceptance is claimed: actual widget content/state and listener paths were exercised directly. Full browser OAuth interaction was not repeated; no username/password field is supplied to GitHub REST.

New regression cases cover request restart/generation races, terminal archival, queue-independent completion, dispatch rejection, policy/account races, explicit custom approval, secret redaction, token cleanup, maximum description size and bounded storage locks. Full suite counts and exact artifact hashes are recorded in the release manifest. Native binary/template/EPF are reused unchanged. Separate form-owner export/editor readiness and modal Native screenshot complaints are not covered by this release.

Both errors (report_type=bug) and improvement proposals (report_type=proposal) use the same explicit title/description and exact approval. Issues have [Bug report] or [Proposal] prefixes; no separate label permission is required. The legacy tool name edt_bug_report remains for compatibility.

Final proposal acceptance: real MCP prepare_async(report_type=proposal), persisted status, SWT exact-text preview and Send produced issue #43 with the exact title/body; it was closed after verification. Final artifact also reverified the saved GitHub account and returned original issue #42 without a new POST.
