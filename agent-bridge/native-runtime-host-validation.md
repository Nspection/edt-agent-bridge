# Проверка Native runtime host — 2026-11-07

Отдельная EDT 2026.1.2.2 / Java 17, собственная новая файловая ИБ 8.3.27.2325. Клиент запущен штатным runtime/access API EDT в управляемом режиме толстого клиента. Пользовательские проекты и базы не использовались.

Два последовательных полных прогона в одной EDT без перезапуска:

- External: новый внешний проект и основная форма созданы фабрикой EDT, EPF собрана IExternalObjectDumper. VAExtension/Vanessa не использовались. Native ZIP подключён через временное хранилище, без постоянной установки.
- Metadata: уникальная обработка и форма созданы в тестовом проекте; FULL reload + EQUAL; EPF-bootstrap открыл встроенную форму. Запрос метаданных до уборки подтвердил наличие обработки.
- В обоих режимах серверный BSL вернул 42 и сохранил русскую строку, emoji, `$literal$` и фигурные скобки; клиентский BSL вернул 43; параметризованный запрос вернул Value=42.
- Намеренное исключение в обоих режимах вернуло success=false и стек 1С. Это не было отмечено успехом транспорта.
- Получены фоновые снимки обоих клиентов через edt_process_snapshot без активации окна.
- cleanup завершился cleaned=true в каждом прогоне. Для metadata дополнительно source_removed=true и database_verified_absent=true: после native удаления/FULL reload отсутствие проверено отдельным серверным запросом из внешней EPF.
- Проверено восстановление уборки после частичного удаления исходников и после перезапуска EDT.

Исправлены обнаруженные при проверке дефекты: игнорирование явной основной формы внешней обработки, неправильный setter основной формы обработок/отчётов, владение памятью имён методов Native API, интервал ожидания 8.3, слишком раннее снятие хеша до материализации проекта, ожидание остановки контекста EDT перед удалением внешнего проекта, незакрытые IFile InputStream в ModuleFileWriter и YAxUnit.

313 Java-регрессий прошли. Включены проверки at-most-once claim, повторного результата, Unicode, восстановления неопределённого исхода, сохранения изменённых/новых файлов, удаления неизменных остатков и закрытия потока при ошибке чтения. Отдельный C++ NativeContractTest проверил выделение/освобождение имён методов через IMemoryManager.

Живой двойной прогон выполнен на native9. Содержимое всех записей финальных core/UI JAR 1.4.0.20261107runtime2 побайтово совпало с этой сборкой, кроме META-INF/MANIFEST.MF с номером версии. Финальный пакет отдельно прошёл 313 тестов и verify-only штатного p2 director в копии профиля.

Убраны все собственные runtime host-проекты/обработки/EPF/ZIP, временные снимки и операции provisioning из Dev workspace. Базовый тестовый проект удалён через Eclipse API; регистрация ИБ — через IInfobaseManager.delete, отсутствие записи запуска проверено отдельно. Физическая тестовая база удалена; собственных клиентов и временного правила доверия не осталось. Приватный helper удаления регистрации снят с установки и удалён с диска. Доказательства сохранены в игнорируемых локальных .runs, не в Git прикладного проекта.

Серверный контекст файловой ИБ не является проверкой серверного кластера. Новый native host отдельно не прогонялся на кластере, платформе 8.5, Linux или веб-клиенте. Произвольный UI, роли реальной бизнес-конфигурации и её обработчики обновления этим fixture не проверяются.
