# Ревью workflow11 — 09.11.2026

Проведены основное ревью и отдельное независимое read-only ревью относительно main ef6c667. Независимый агент проверил фактические изменения и повторно прочитал исправления; в финальном заключении блокирующих замечаний не осталось. Файлы он не менял, EDT/1С и тесты сам не запускал.

Исправленные замечания:

- Summary и compact сохраняют вложенные отрицательные outcomes, включая result.execution.success=false. Даже явный fields/result нельзя выбросить ради byte budget с сохранением видимого DONE; при нехватке места возвращается details_required.
- На границе глубины evidenceTree не возвращает исходный payload. Код, аргументы, значения, строки результатов и логи исключены из outcome-проекции; глубина/размер отмечаются evidence_complete=false/evidence_truncated=true. Known evidence arrays (unknown_sections/blockers) сохранены; длинные вложенные ошибки имеют *_truncated.
- database=connected не принимает isConnected(project,ref) за доказательство выбранной ИБ. SDK даёт контейнер проекта; готовность connected остаётся неподтверждённой. bound и equal сохраняют свои отдельные требования.
- edt_ready проверяет global services без обхода readiness посторонних проектов; модель выбранного проекта проверяется отдельно.
- Каталог разбирает числа схем как BigDecimal. Изменение maximum между 9007199254740992 и 9007199254740993 меняет хеш и сохраняется в выдаваемой схеме.

Проверены durable batch/step keys, отсутствие автоматического replay при outcome_unknown, client-binding guard, чтение деталей без переисполнения, метрики без payload и read-only ошибки. Неизвестный исход изменяющей операции не получает разрешение на автоматический повтор.
