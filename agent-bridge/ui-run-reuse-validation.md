# Проверка повторного использования UI-клиента — 11.11.2026

Релиз `1.4.0.20261111reuse1`. Прежний ui1 не поддерживает новое поле
reuse_from_ui_run_id; сверять установленный контракт.

Реализованы повторное использование собственного TestClient, компактный итог,
стабильные diagnostic.code/next_step и подсказки выбора Native/TestClient/Vanessa
в компактном каталоге и контракте. Новых фасадов нет: остаются десять.

## Живая проверка

Собственная EDT Agent Bridge Dev, отдельный workspace/MCP8769,
1С8.5.1.1522; одноразовый BridgeCreationUiReuse90cc74cc, UUID 71c81bd5-c642-4e39-b6c0-8247a5c106b9.
Dev2: исходный пакет открыл список и подтвердил форму, сохранив клиент.
Следующий пакет новым ключом и reuse_from_ui_run_id прошёл на том же PID/времени
старта и client_id. Backend reuse не вызывает prepareEnvironment/startClient.
Повтор ключа вернул исторический результат. Несуществующий элемент дал
неуспешное условие, cleanup пакета оставил клиент владельца живым. Затем свежий
preview/hash владельца и cleanup остановили исходный клиент, cleaned=true.
Невалидная комбинация двух разных ожидаемых окон была отклонена preflight;
исправлен тестовый план, а не повторена отправленная мутация.

Первый пакет с подготовкой: 38164мс; повторный: 1154мс.
Это один сценарий; операции и объём работы различались, это не общий benchmark.
Обычный ответ: 1517байт, details: 4355байт (65.2% меньше).
Это размер UTF-8 JSON, не измерение токенов. Полные значения и тайминги сохранены.

## Заключительные проверки

Dev4: 817 Java-тестов и standalone product boundary. Проверены: одинаковый ключ,
смена UUID/проекта/вида клиента, потеря канала без повторного запуска, неизвестный
исход заимствованного пакета, запрет параллельного пакета и уборки владельца,
компактный контракт/диагностика и сохранение details. Между dev2 runtime и dev4
менялись только краткое представление UiRunService и текст фасада; JAR-сравнение
подтвердило неизменность backend/worker/запуска. UI-прогон dev4 отдельно не повторялся.
p2 verifyOnly на скопированном профиле и частной установке прошёл (exit0);
результат сохранён в .runs/ui-reuse/p2-verification.json. Python-worker не менялся.

## Уборка и пределы

Свои клиент, новая база, регистрация и проект удалены. Частная EDT закрыта,
bundles.info/1cedt.ini побайтно восстановлены. Собственные receipts архивированы
в .runs/ui-reuse/evidence; отчёты оставлены как доказательства. Пользовательская
EDT/базы не использовались. Порт отладки1552 не настраивался и процессы пользователя
не останавливались. Git-изменения x5 не затрагивались.

Не проверялись карта/ЦО TMS, произвольные сторонние формы, кластер, рестарт/падение
реальной EDT посреди записи. Рестарт и неизвестные исходы покрыты контрактами,
но не объявляются полноценной crash-приёмкой. Уборка runtime не удаляет бизнес-данные;
для живого теста удалена целиком только собственная одноразовая база.
