# Типизированные элементы прямого TestClient

В `edt_form_state` (`transport=testclient`, `view=elements`) поле `potential_actions` показывает действия для распознанного типа. Это не подтверждение видимости, доступности или поддержки конкретного прикладного обработчика. Перед отправкой проверяются текущее окно, форма и дескриптор элемента.

| Элемент | Действия | Подтверждение |
| --- | --- | --- |
| Поле ввода | `input`, `open_choices`, `choose_value`, `activate`, `increase`, `decrease` | Текст; для выбора — единственный точный пункт; для числового поля — изменение в заданную сторону |
| Флажок, тумблер | `check`, `uncheck`, `activate` | Известное `Да/Нет` или `Yes/No`, переключение только при отличии, затем чтение |
| Переключатель вариантов | `open_choices`, `choose_value`, `activate` | Точный уникальный текст варианта и чтение результата |
| Страница | `tab`, `activate` | `GET_CURRENT_PAGE`, а не `CURRENT_VISIBLE` |
| Обычная группа | `expand`, `collapse` | Подтверждение команды; для проверки результата нужен явный `expect` |
| Кнопка | `command`, `activate` | Подтверждение команды либо точный фокус; бизнес-результат проверяется `expect` |
| Декорация/поле надписи или картинки | `command` | Подтверждение команды; переход проверяется через явный `expect` |
| Календарь | `set_date`, `activate` | `date=YYYY-MM-DD`, корректная дата и подтверждение команды. Scalar-чтение календаря не поддержано: результат проверяется отдельным связанным полем через `expect`; сам `control.state_verified` остаётся false |
| Ползунок | `set_position`, `activate` | `position=0..100` — процент команды. Это не значение шкалы; для подтверждения передать `value` с ожидаемым отображаемым значением или явный `expect` |
| Плоская таблица | Прежние `table_*`; `cells` принимает строку для InputField и boolean для CheckBoxField | Точная строка/текущая ячейка, установка только отличающегося флажка и повторное чтение после завершения редактирования |

Новые действия доступны через прежний `edt_form_action`, отдельный новый MCP-инструмент не нужен. Они также входят в `steps` прямого `batch` и единого `edt.run op=ui`; в едином прогоне каждому изменяющему шагу по-прежнему нужен `expect`. Для календаря обязательно непустое `expect.fields` по отдельному связанному скалярному полю: одно совпавшее окно/видимость не подтверждает дату. Запрос собственного Calendar-поля в `expect.fields` отклоняется до отправки. Маршрутизатор учитывает эти имена при выборе TestClient.

`open_choices` возвращает до 256 вариантов в пределах 64 KiB, открывая выпадающий список при необходимости. Значение не выбирается. Для исходно не выбранного radio прежнее значение может быть неизвестным (`value_before=null`, `changed=null`); выбор всё равно требует точного уникального варианта и чтения нового значения.

`choose_value` не вводит текст вместо выбора ссылки: открывает выпадающий список, требует точный единственный вариант и повторно проверяет список. Возвращаемый текст не доказывает идентичность ссылочного объекта. Неподдерживаемый диалог выбора требует отдельного маршрута.

Текстовые/табличные документы, HTML, диаграммы, планировщик и другие сложные виджеты не объявляются редактируемыми без проверенного контракта. Нет произвольных GUID, координат, клавиатуры или скрытого выполнения BSL вместо TestClient. Для BSL/данных остаётся Native, для необходимых сложных сценариев — Vanessa.

Смена формы до отправки блокирует действие. После отправки команда не повторяется из-за непроверенного результата. Неполный протокольный ответ сохраняет прежний запрет новых мутаций; отрицательный ответ на чтение списка вариантов сам по себе не разрушает транспорт. Пакет не является транзакцией и не откатывает данные.

Прикладное подтверждение внутри `input` может вернуть полный отрицательный ответ на действие и оставить открытый диалог. Это `outcome_unknown=true`, `mutation_blocked=true` при `transport_state=usable`: доступны наблюдение, результат исходной операции и уборка. Новый ключ, другой клиент или Native не разрешают повтор той же неизвестной операции. В собственной TMS это воспроизведено предупреждением о редактировании наименования; автоматического ответа нет. Разовый ответ после точного явного разрешения доступен через [контракт прикладных подтверждений](testclient-confirmations.md); исходный результат и общий barrier сохраняются.

Пустая таблица без доказуемого набора строк возвращает `table_rows_unproven`; это не нулевое количество и не успешное добавление. Команды выделения могли выполниться, но ввод данных не отправляется. Клик по полю-надписи может открыть штатный диалог отображения значения; результат прикладного обработчика и диалог нужно проверять отдельно.
