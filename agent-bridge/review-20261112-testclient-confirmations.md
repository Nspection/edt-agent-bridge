# Приёмка прикладных подтверждений TestClient — 12.11.2026

Кандидат `1.4.0.20261112zzzzzzzdialogs4`. Проверки только в собственной EDT/маркированной TMS_TEST_AGENT, Windows x64, платформа 8.5.1.1522. Пользовательская EDT, TMS_FILE85, отладочный порт 1552 и x5-исходники не использовались.

## Ревью и регресс

Своя проверка кода и независимое ревью завершены до релиза. Исправлены обнаруженные замечания: побочная ошибка observe при добавлении внутреннего operation_id; смена текста/кнопок без смены handle; неверный next_call при ошибке самого ответа. По собственной проверке дополнительно запрещены недоказанные window/form/target handles. Открытых подтверждённых P1/P2 нет. Независимый рецензент самостоятельно повторил 18 Python-проверок и diff --check; EDT/базу он не запускал.

Финальный набор: **1060 Java + 124 Python** (65 worker, 19 table, 22 controls, 18 dialogs). Standalone boundary PASS. Проверены exact grant/base/operation, смена текста во время чтения flags, hidden/unknown buttons, missing handle, повтор ответа, неизвестный/полностью отрицательный ответ, сохранение исходного barrier, отсутствие capture при read/not_sent/timeout, посторонний поздний диалог и обрыв во время capture.

## Живые проверки

Реальный input Наименования новой несохранённой карточки вызывает прикладной MessageBox85 о нежелательном редактировании. Исходный ответ полный отрицательный: transport usable, pending replies 0, outcome_unknown true. Диалог фиксируется worker немедленно за исходным operation_id; inspect возвращает точный текст и только Да/Нет, скрытые Command2..8 не предлагаются.

На dialogs2 ответ «Да» подтверждён штатным CLICK action/commit; после него чтение Наименования возвращает пустую строку. Исходный ввод не объявлен успешным. На финальном dialogs4 отдельно пройден «Нет»: полный ACK, диалог закрыт, карточка снова читается, поле пустое. Это два самостоятельных заранее определённых теста, без повторения неизвестного ввода. Команда записи карточки не отправлялась.

Неверная база и отсутствие authorization отклонены до ответного claim. Повтор того же ключа вернул journal; новый ключ для того же диалога и обычный новый input отклонены. Исходная запись осталась outcome_unknown; can_observe true, can_mutate false. Тот же ключ ответа после stop прочитан из journal без живого клиента. Финальный исходный результат содержит корректный next_call dialog_inspect.

После холодного запуска первый TestClient start остановлен защитой native EQUAL до запуска клиента. Штатный read-only refresh подтвердил EQUAL/NO_CHANGES/configuration_updated=false; следующий разрешённый запуск прошёл. Защита не ослаблялась, FULL-обновление не выполнялось.

## Границы и измерения

Regex privileged topics — только дополнительный denylist, не security-классификатор. Не тестировался обход/автоответ реальных trust/password/license/security вопросов; они вне контракта. Пользовательское семантическое разрешение обязательно. Автоматическое снятие barrier и продолжение input не реализованы.

Производственный transport timeout не воспроизведён и не объявлен исправленным. Selecting_python измерен: 6824 мс в dialogs2 и 8194 мс в dialogs4; оптимизация и ослабление проверки Python не выполнялись. Native DLL/протокол/host template и закреплённый vendor не менялись.
