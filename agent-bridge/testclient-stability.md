# Устойчивость прямого TestClient

С 1.4.0.20261111zzzzzzzzzstable1 общий бюджет операции/batch и ожидания полного протокольного ответа по умолчанию60с. Прежние значения25с для операции и10с для ответа могли разорвать канал при ещё допустимом медленном чтении. operation_timeout_s5..300 по-прежнему задаётся агентом; readiness_timeout_s90 по умолчанию относится отдельно к запуску. Внешний worker reply budget — операция+10с; таймаут MCP для прямого observe учитывает его.

wait_timeout_ms ограничивает повторные проверки условия; уже начатый ответ дочитывается в общем бюджете. Один бюджет относится ко всему batch. Явные постусловия по умолчанию10с, observe1500мс, wait5000мс; это не обязательные паузы. Для сложной карты задавать наблюдаемый expect и явный бюджет, например operation_timeout_s90/wait_timeout_ms60000.

Ошибка операции и здоровье транспорта разделены:

- condition_timeout — условие не подтверждено; выполненные шаги сохраняются, канал может быть исправен.
- operation_timeout с last_rpc_phase=not_sent — vendor подтвердил, что текущий кадр не отправлен. Это не потеря соединения. Более ранние изменения в том же шаге/пакете не стираются.
- operation_rejected — полный отрицательный ответ на чтение. Можно диагностировать состояние/диалоги через тот же канал. Отказ после попытки изменения остаётся консервативным outcome_unknown.
- transport_failed/broken — неполный ответ, разрыв или недоступный worker. Нельзя отправлять следующую команду в поток с неподтверждённой границей кадра. Автоматического resync/reconnect/replay нет.

outcome_unknown не равен broken. Если поток исправен, он остаётся доступным для observe/status/result, но новые action/batch блокируются и worker, и долговечным журналом клиента. Новый idempotency_key не снимает запрет. status возвращает mutation_blocked/blocking_operation_id/can_observe/can_mutate; connected само не означает разрешение изменять форму. Незавершённый текущий claim также блокирует параллельную мутацию. Исходный ключ возвращает сохранённый результат до проверки живого процесса, в том числе после остановки клиента. После cleanup подробности удалены; старый ключ не восстанавливает их.

Диагностика результата и status.last_failure содержит только метаданные: этап, failed_step_index, PID worker/клиента, порт, elapsed/budget, число RPC, вид/фазу последнего RPC и доступные счётчики приёма. Если vendor уже сбросил буферы при закрытии, недоступные счётчики равны null, а не доказанному нулю. В диагностике нет значений полей, текстов протокольных кадров, форм, BSL или секретов. last_failure — историческая запись с временем/operation_id, не текущее состояние процесса. Полный результат сначала сохраняется в журнал, статусная диагностика записывается best-effort и не подменяет результат.

Краткие edt_form_action и edt.run op=ui сохраняют transport_state, reason/stage, execution_state и diagnostics. Ошибка начального наблюдения UI сохраняется до отправки изменений. Большие значения/деревья по-прежнему остаются в details. Запрос, превышающий128KiB UTF8, отклоняется до claim и передачи worker.

При сбое читать исходные job/operation_id и status.last_failure; не запускать ту же мутацию новым ключом, новым клиентом или другим исполнителем автоматически. Для данных/BSL остаётся Native, для пользовательских команд — TestClient. Native-снимки могут подтвердить вид формы, но не выполнение её пользовательских команд.

Приёмка выполнена в собственной новой базе8.5.1.1522/Windows x64 с тонким TestClient: реальная форма с HTTP-задержкой сервера32с открылась за32.27с, закрылась и продолжила чтение по тому же каналу. Принудительная остановка только своего подтверждённого процесса дала outcome_unknown и диагностику. Точный сбой пользователя в TMS и живой модальный диалог этим не воспроизведены. Native DLL, host, BSL-шаблон и протокол не изменялись.

При превышении256KiB ответа worker возвращает bounded result_too_large с исходными outcome/action/health, execution_success, snapshot_id и счётчиками шагов. Значения/деревья опускаются; большой ответ сам по себе не закрывает исправный канал и не превращает чтение в неизвестную мутацию. Нельзя повторять изменение ради получения подробностей — читать более узкую область. Граница входного JSON128KiB учитывает отдельный завершающий newline.
