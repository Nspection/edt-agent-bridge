# Ревью сетки и линеек на снимках

Ревью полного diff относительно e3de97c и отдельное независимое ревью проверили параметры компактных/legacy-контрактов, общую отрисовку EDT/Native, исходные байты и SHA256, пиксельные координаты, сохранение контекста request_id, защиту изменённых копий, квоты и уборку.

Независимый harness подтвердил два P2:

1. Два допустимых PNG 5120×4096 проходили последовательно, но параллельно вызывали OutOfMemoryError при -Xmx256m. Теперь общий fair lock охватывает чтение/декодирование/отрисовку/кодирование, до выделения растров, отдельно от SWT gate. Тот же harness подтвердил sequential PASS и parallel errors=0.
2. После успешного EDT-capture ошибка квоты/папки аннотации скрывала путь оригинала. Теперь EDT и Native используют decorateOrReport: исходный ответ сохраняется, alignment_error/false обозначает partial. Batch не объявляет его полным успехом. Изолированный PartialProbe и финальная MCP-проверка подтвердили сохранность оригинала и блокирующего/изменённого файла.

Публикация производного PNG выполняется через временный файл и rename без REPLACE_EXISTING. При отказе временный файл убирается; изменённая копия сохраняется. Повторное независимое ревью новых подтверждённых P1/P2 не нашло.

882 Java-теста, standalone boundary, 41 worker и 16 table контрактов прошли. Private p2 verifyOnly использует копию профиля; после merge проверяется эквивалентность JAR, после публикации — GitHub assets, публичные p2 SHA256 и resolver обычного URL.

Живая приёмка финального JAR в отдельной EDT: batch20/40, preview50, legacy original-only; занятая папка alignment → original + partial, редакторы убраны. Native: неизменённый реальный Windows capture собственной fixture → authenticated channel; MCP action=snapshots проверил SHA256, копию, partial после изменения копии и прежний ответ без grid. Это проверка снимков и наблюдения, не исполнения прикладной формы 1С. Платформа/Native ZIP не менялись, новая база и пользовательская EDT не запускались. Собственные проект/снимки/процессы убраны, private configuration восстановлена. Снимки визуально просмотрены при первичной приёмке; после исправления использовался тот же renderer.
