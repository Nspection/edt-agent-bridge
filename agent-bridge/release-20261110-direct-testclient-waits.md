# EDT Agent Bridge 1.4.0.20261110zzzwaits1

Прямой TestClient теперь дожидается готовности окна перед успешным запуском. В пакетах можно явно ждать нужную форму, значения и доступность полей; после команды проверка результата также допускает ограниченное ожидание.

- `action=wait`: точный заголовок/имя формы, текстовые значения и boolean-состояния visible/enabled/readonly. Таймаут прекращает пакет; следующие команды не отправляются.
- `response_mode=summary`: краткий итог шагов, проверок и снимков состояния. Полный результат доступен по operation_id. Прежний полный ответ сохраняется по умолчанию.
- MCP явно рекомендует встроенную подготовку Python без ручного venv/pip; статус needs_setup содержит точный next_call.
- Повторяются только наблюдения. Запись/нажатие не повторяются; неизвестный исход требует разбора первоначальной операции.
- Основное и независимое ревью: исправлены смешивание экземпляров формы, ошибочное закрытие канала при гарантированно неотправленном чтении и счётчики одиночного summary.

708 Java-тестов и46 Python-контрактов. В собственной базе на1C8.5.1.1522 проверены9 шагов сохранения/повторного открытия, повтор ключа и остановка по таймауту. В этом сценарии JSON-ответ компактнее примерно на56%; это измерение размера ответа, не числа токенов.

Только Windows/прямой TestClient с подготовленной Python-средой; общий I/O-бюджет запроса25с, отдельное ожидание до10с, пакет до16 шагов. Это не транзакция, отката предыдущих записей нет. Идентификаторы снимков в summary относятся к состоянию формы; существующие PNG-механизмы сохранены.

Пользовательская EDT и базы не использовались. Собственные тестовые ресурсы убраны, исходное состояние тестовой EDT восстановлено.
