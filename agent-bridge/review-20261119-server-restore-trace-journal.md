# Проверка журнала восстановления DT и блокировки по трассировке

На изолированной EDT 2026.1.2.2 и копии серверной ИБ 1С 8.3.27.2325 с PostgreSQL 11.5 проверены две конфигурации. При активной штатной трассировке короткий статус MCP вернул edt_command_tracing_active, blocked_before_stage=preflight, import_completed=false и operator_action=keep_edt_tracing_unchanged. В рабочем каталоге операции был журнал с итоговым кодом блокировки. Резервная копия и импорт не запускались. Состояние трассировки отдельно проверено после отказа.

Отдельный вызов штатного SDK для резервного копирования тестовой базы создал непустой DT. Нативная трасса содержала значение синтетического пароля в аргументе /P. Значение удалено из пробных журналов после проверки. Реквизиты рабочей базы не использовались.

С выключенной трассировкой на стенде последовательно выполнены резервное копирование, импорт, проверка входа экспортом, привязка и первый FULL. Результат равен EQUAL. Журнал содержал только события этапов, время, длительность и итог. Собственные EDT, кластер и PostgreSQL остановлены. Пользовательская EDT и рабочие базы в прогоне не участвовали.

Целевые тесты покрывают недоступность состояния трассировки, блокировку после подтверждённого импорта и сбой записи подтверждения. При последнем Bridge сообщает, что импорт завершён, и сохраняет блокировку повтора. При неизвестном результате публикуется outcome_unknown без import_completed. Полный успешный прогон включает 1429 Java-тестов.
