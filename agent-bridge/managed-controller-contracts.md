# Контракты контроллера managed Vanessa

Контроллер принимает прежние действия `Start`, `Status`, `Stop`, `Continue`, `PauseClock`, `ResumeClock` и `Prepare`. Точка входа `run-vanessa-debug.ps1` читает параметры CLI и выполняет операции Windows. Соседний `managed-vanessa-core.ps1` содержит функции, вызываемые штатной точкой входа и тестом `tools/test-managed-controller.ps1`. Загрузка файла определяет функции без выполнения действий контроллера.

## Соответствие прежней обязательной стадии

Номера соответствуют порядку проверок в историческом протоколе. Итоговые группы в нём имели накопительные счётчики 13, 18, 22, 24, 29, 32 и 33. В тесте проверяются результаты и отсутствие запрещённых эффектов. Неизвестное состояние контроллера прерывает операцию.

| № | Входные условия | Что проверяет тест в рабочем коде |
|---|---|---|
| 01 | Неполный запрос Continue | `Invoke-MvContinuation` отклоняет запрос до наблюдения формы |
| 02 | Чужой RunId | Отказ до обращения к данным контрольной точки |
| 03 | Чужой CheckpointId | Отказ до обращения к данным контрольной точки |
| 04 | Снимок изменился | Расхождение SHA исключает сигнал продолжения |
| 05 | Состояние stopped | Остановленный запуск не продолжает сценарий |
| 06 | Исчерпан бюджет времени | На границе TimeoutSeconds запрос отклоняется |
| 07 | Готовность контрольной точки устарела | На границе 180 секунд запрос отклоняется |
| 08 | Все свидетельства совпали | Следует одно наблюдение и один сигнал продолжения |
| 09 | Сигнал уже установлен | Повторное обращение не подаёт второй сигнал |
| 10 | Stop с чужим RunId | `Get-MvStopScope` отклоняет обращение до получения разрешения на остановку |
| 11 | Нечитаемое состояние JSON | `Read-MvState` прерывает обработку |
| 12 | Stop с RunId, состояние отсутствует | Возвращается `absent` до поиска процессов |
| 13 | Во время остановки менеджера появился клиент | `Invoke-MvStopOwned` с `Select-MvOwnedProcesses` обнаруживает своего клиента повторным чтением и сохраняет посторонний процесс |
| 14 | Preview, перенаправление ConfLocation | `Get-MvTrustPlan` выбирает конечный файл, `Invoke-MvTrustPlan` оставляет журнал эффектов пустым |
| 15 | Настройки платформы, общей папки и пользователя | Сохраняются сторонние правила, прежние варианты правила заменяются одним точным правилом менеджера. Резервирование всех трёх файлов предшествует первой записи |
| 16 | Повтор утверждённого плана | Новая подготовка того же состояния не создаёт резервных копий и не требует перезапуска |
| 17 | Хеш пакета отличается от ожидаемого | Подготовка запрещена |
| 18 | Базы менеджера и приложения совпадают | Подготовка запрещена |
| 19 | Отладчик поставил часы на паузу | `Get-MvElapsed` и `Test-MvWatchdog` учитывают только активные секунды |
| 20 | Повтор PauseClock | `Set-MvClock` сохраняет исходную отметку паузы |
| 21 | ResumeClock | Потраченное на паузу время вычитается из бюджета |
| 22 | PauseClock для чужого RunId | Запрос отклоняется |
| 23 | Интерактивный шаблон | `New-MvLaunchPlan` включает выполнение сценариев, отчёт JUnit и компоненты скриншотов |
| 24 | Каталог платформы без версии 8.5 | Команда содержит штатные флаги, ключ `/i85` отсутствует |
| 25 | ManagerMcpPort не задан | MCP не включается по умолчанию |
| 26 | Порт задан явно | В аргументах менеджера одновременно присутствуют порт, StartFeaturePlayer и VAParams |
| 27 | Порт уже занят | `Invoke-MvAfterPortCheck` прекращает подготовку запуска до создания каталога результата |
| 28 | Порт принял чужой процесс | `Test-MvListener` и `Confirm-MvManagerStartup` отклоняют соединение, запрашивают уборку своей сессии и сохраняют stopped |
| 29 | Владелец порта изменился во время работы | `Get-MvManagerStatus` сообщает об ошибке и сохраняет RunId для точной уборки |
| 30 | Серверная цель, обычная платформа | Клиент получает строку Srvr/Ref без `/i85` |
| 31 | Остановка после запуска | Запрашивается удаление только va-params.json своего каталога |
| 32 | Платформа 8.5 | В команде менеджера присутствует `/i85` |
| 33 | Минимальный шаблон с визуальной точкой | План содержит текст производного feature, его имя и оба каталога в параметрах Vanessa |

Дополнительные отрицательные векторы меняют свидетельства доступности снимка и клиента, повторно используют PID с другой датой создания, убирают маркер владения, имитируют отказ при резервировании конфигурации и отсутствие слушателя. Проверка владельца разбирает точные аргументы менеджера и клиента. Совпадение пути по префиксу или внутри постороннего параметра больше не разрешает остановку процесса. Существующий пустой файл состояния, JSON null и некорректная структура отклоняются. Положительные векторы проверяют окончание бюджета без паузы и владельца нужного порта.

## Границы исполнения

Контракты 01–33 используют объекты и журнал эффектов в памяти. Тест не подменяет системные команды PowerShell, не создаёт исполняемые файлы и настройки доверия, не меняет LOCALAPPDATA, не открывает сетевые порты и не вызывает остановку процессов. В конце тот же PowerShell вызывает настоящий CLI с новым маркированным пустым каталогом. Проверяются idle Status, отказ Continue без активного запуска и absent Stop. Уборка перечисляет созданные файлы и удаляет только пустые каталоги.

Такая проверка подтверждает решения контроллера, интерфейс CLI на трёх путях и передачу эффектов адаптеру. Она не подтверждает живую работу CIM, сетевого слушателя, запуска 1С или записи платформенных настроек. Для этих путей сохраняются отдельные разрешённые интеграционные проверки. Состав поставки должен включать точные байты обоих файлов контроллера и совпадающие копии ресурсов PDE.
